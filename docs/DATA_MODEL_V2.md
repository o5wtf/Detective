# Detective — Модель данных v2 («Слои и замки»)

> Технический документ к [DESIGN_DOC_V2.md](DESIGN_DOC_V2.md): формат дела, id, состояние партии, сохранение, проверки. При расхождении прав диздок. Работа ИИ с данными — `AI_PROTOCOL_V2.md`, код — `ARCHITECTURE_V2.md`, полный пример — [examples/library_night.json](examples/library_night.json).

---

## 1. Общие соглашения

- **Формат.** Одно дело — один файл JSON в UTF-8. Встроенные дела лежат в `res://cases/<id>.json`, пользовательские — в `user://cases/<id>.json`.
- **Имена полей** — английский `snake_case`. Тексты для игрока и ИИ пишутся на языке дела (по умолчанию русский).
- **Обязательность.** Поле обязательно, если не указано значение по умолчанию (тогда его можно не писать). Тексты не пустые, если не помечены «можно пустым».
- **Время** — `"HH:MM"` или `"N HH:MM"`, где `N` — день дела (по умолчанию 1), §2.4. **ИИ** в таблицах — поле только для промпта, игрок его не видит.
- **Условия.** Замки слоёв и условия открытия улик записываются одинаково: **список способов**, где каждый способ — это список условий, которые нужны все. Условие выполнено, если выполнен хотя бы один способ. `[[A, B], [C]]` значит «A и B, либо C». Пустые списки запрещены. Так выражается любая комбинация «И» / «ИЛИ»; в редакторе это «Способ 1, Способ 2…» с кнопкой «+ способ».

## 2. Файл дела

### 2.1. Корень

| Поле | Тип | Что это |
|---|---|---|
| `schema_version` | число, всегда `2` | Версия формата. |
| `id` | id | Паспорт: идентификатор дела. По нему называется файл сохранения. |
| `title` | строка | Паспорт: название в списке дел и на экранах. |
| `briefing` | строка | Брифинг: завязка, жертва, обстоятельства. Видят игрок и ИИ-актёр. |
| `atmosphere` | строка, можно пустым | Стиль и тон дела. **ИИ**. |
| `time_window` | `{ "start", "end" }` | Общие для дела `t1` и `t2`, §2.4. |
| `starting_character_id` | id персонажа | С кем игрок начинает расследование. |
| `characters` | массив, не пустой | Персонажи, §2.2. Порядок в массиве — порядок в списке персонажей. |
| `evidence` | массив | Улики, §2.6. Порядок — порядок на доске улик. |
| `conflicts` | массив, по умолчанию `[]` | Конфликты для несостыковок, §2.7. |
| `finale` | объект | Обвинение и финальный текст, §2.8. |

Списки стартовых улик и участников на брифинге собираются из `evidence` и `characters`.

**Версия дела (хеш)** — отдельного поля нет. Это SHA-256 от канонической записи содержимого: файл разобран, значения по умолчанию подставлены, ключи по алфавиту, без пробелов, UTF-8. Пересохранение и отступы хеш не меняют, правка содержимого меняет — и старое сохранение не загрузится (§5); редактор об этом предупреждает.

### 2.2. Персонаж (`characters[]`)

| Поле | Тип | Кто видит | Что это |
|---|---|---|---|
| `id` | id | — | Идентификатор. |
| `name` | строка | игрок, ИИ | Имя. |
| `gender` | `male` \| `female` | ИИ, движок | Род в речи ИИ и подбор голоса. |
| `role` | строка | игрок, ИИ | Место в деле в 2–3 словах, подпись под именем. |
| `biography` | строка | **ИИ** | Краткая история жизни и характера. |
| `appearance` | строка | игрок, ИИ | Внешность: одежда, приметы, возраст. |
| `behavior` | строка | игрок, ИИ | Как держится: осанка, жесты, мимика, привычки. |
| `dialogue_goal` | строка | **ИИ** | Чего добивается и чего избегает в разговоре. |
| `speech_style` | `{ "description", "sample_lines" }` | **ИИ** | Манера речи: описание и примеры реплик (`sample_lines` по умолчанию `[]`). |
| `starting_emotion` | эмоция из списка | игрок, ИИ | Стартовая эмоция. Текущая хранится в состоянии партии (§4.2). |
| `attitude_to_investigator` | строка | **ИИ** | Отношение к следователю, пока статичное. |
| `profanity` | `never` \| `sometimes` \| `often` | **ИИ** | Уровень мата. |
| `greeting` | строка, можно пустым | игрок | Первая фраза при первой встрече. Её произносит движок, а не ИИ. |
| `relationships` | массив, по умолчанию `[]` | **ИИ** | `[{ "character_id", "text" }]` — как он воспринимает других. |
| `timeline` | массив, по умолчанию `[]` | **ИИ** через картину мира | Таймлайн, §2.4. |
| `facts` | массив, по умолчанию `[]` | **ИИ** через картину мира | Вне-таймлайновые факты, §2.4. |
| `layers` | массив, по умолчанию `[]` | **ИИ**, только активные, без замков | Верхние слои-легенды, §2.5. |
| `voice` | `{ "tts_voice", "voice_style", "filler_lines" }` | движок | Голос TTS, подсказка стиля озвучки и фразы-заполнители. Если `filler_lines` пуст, движок берёт стандартные («Хм…», «Секунду…»). |

**Эмоции** (для `starting_emotion` и ответов ИИ): `calm`, `neutral`, `nervous`, `scared`, `sad`, `angry`, `controlled`, `contemptuous`. Признака «подозреваемый / свидетель» нет — статус понятен из `role`.

### 2.3. Что получает ИИ-актёр

Все поля с пометкой «ИИ» и «игрок, ИИ», текущую эмоцию и вместо `timeline`/`facts`/`layers` — собранную кодом картину мира (§2.5.4) вместе с подробностями (`details`) и слабыми местами легенд (`weak_spots`). Замки, неактивные слои, правда под ними (и её подробности) и данные других персонажей в промпт не попадают никогда.

### 2.4. Таймлайн и вне-таймлайновые факты

**Время** — строка `"HH:MM"` (24 часа) с необязательным номером дня дела впереди: `"18:00"` — день 1, `"2 09:30"` — день 2, 09:30. Дни — порядковые дни дела, а не даты; день 1 можно не писать (редактор его не пишет). Для сравнения код переводит время в минуты: `(день − 1) × 1440 + часы × 60 + минуты`.

**Окно времени** `time_window: { "start", "end" }` — общие для дела `t1` и `t2`, `start` < `end`. Один вечер: `"18:00"`–`"23:00"`. Через полночь: `"22:00"`–`"2 02:00"`. Несколько дней: `"09:00"`–`"3 21:00"`. Длина окна не ограничена.

**Как время показывается.** Если всё окно лежит в дне 1, игроку, ИИ и в блокноте время показывается как `HH:MM`. Иначе — `день N, HH:MM` (в записи блокнота день у второго времени отрезка пишется, только если он другой).

Таймлайн двухуровневый: отрезки «где был», внутри них отрезки «что делал», внутри тех — точки-события. **Пропуски разрешены**: таймлайн не обязан покрывать всё окно, а «что делал» не обязаны покрывать весь свой «где был». Как ИИ отвечает про время вне таймлайна — в `AI_PROTOCOL_V2.md`.

**Отрезок «где был»** (`timeline[]`):

| Поле | Тип | Что это |
|---|---|---|
| `id` | id | Идентификатор, он же id показания (§3.2). |
| `from`, `to` | время | Внутри окна, `from` < `to` (отрезок может переходить через полночь: `"23:00"`–`"2 01:00"`). |
| `place` | строка | Где был. |
| `details` | строка, по умолчанию `""` | Подробности, §2.4.1. |
| `notebook_important` | bool, по умолчанию `true` | Записывать ли в блокнот, когда персонаж это озвучил. |
| `activities` | массив, по умолчанию `[]` | Отрезки «что делал» в этом месте. |

**Отрезок «что делал»** (`activities[]`): `id`, `from`, `to` (внутри своего «где был»), `text` (чем занимался), `details`, `notebook_important` (по умолчанию `true`), `events` (по умолчанию `[]`).

**Точка-событие** (`events[]`): `id`, `time` (внутри своего «что делал»), `text` (что произошло: кого увидел, с кем поссорился), `details`, `notebook_important` (по умолчанию `true`).

**Вне-таймлайновый факт** (`facts[]`): `id`, `text` (долг, владение ключом, тайное знание), `details`, `notebook_important` (по умолчанию `true`). У всех `details` по умолчанию `""`.

Отрезки одного уровня идут по порядку и не пересекаются. Всё, что лежит в `timeline` и `facts`, — **правда** персонажа. Ложь задаётся только слоями. Пересечения персонажей автор описывает у обоих, каждого со своей стороны.

#### 2.4.1. Подробности (`details`) и слабые места (`weak_spots`)

`text` (и `place`) — короткая строка: её видно на таймлайне редактора, из неё собирается запись блокнота. `details` — необязательный длинный свободный текст к тому же элементу: обстановка, точные слова, действия, чувства персонажа. Чем он богаче, тем живее допрос и тем меньше ИИ выдумывает. У легенды есть ещё `weak_spots` — где эта версия трещит: в чём персонаж путается, что не может объяснить, на что болезненно реагирует (§2.5.2).

- Оба поля необязательные, загрузчик принимает их отсутствие или пустую строку.
- ИИ-актёр получает подробности вместе с элементом, который он сейчас видит (правда или активная легенда), а `weak_spots` — вместе с активной легендой. Подробности скрытой правды так же секретны, как сама правда: пока слой не снят, их в промпте нет.
- В блокнот и служебные проверки подробности не идут.

### 2.5. Слои-легенды (`layers[]`)

Слои — это дерево: в `layers` персонажа лежат верхние слои, а под каждым слоем в `sub_layers` лежат те, что откроются после его снятия.

| Поле | Тип | Что это |
|---|---|---|
| `id` | id | Идентификатор слоя. Если легенда что-то утверждает (а не только скрывает), это и id её показания. |
| `target` | `{ "type", "ids" }` | Что прикрывает слой, §2.5.1. |
| `legend` | объект | Что персонаж говорит вместо правды, §2.5.2. |
| `events_default` | `hide` \| `keep`, по умолчанию `hide` | Только для целей `activity` и `place`: что происходит с событиями внутри, если их нет в `replacements`. |
| `replacements` | массив, по умолчанию `[]` | Только для `activity` и `place`: `[{ "event_id", "text" }]` — события внутри, которые персонаж подменяет другими. |
| `lie_motive` | строка | Зачем персонаж держится этой версии. **ИИ**, только пока слой активен. |
| `lock` | условие (§1) или `null` | Замок, §2.5.3. `null` — слой не снимается никогда. |
| `sub_layers` | массив слоёв, по умолчанию `[]` | Слои под этим. У слоя с `lock: null` их быть не может. |

#### 2.5.1. Цель слоя (`target`)

| `type` | `ids` | Что прикрывает (охват) |
|---|---|---|
| `event` | одно событие | Само событие. |
| `fact` | один факт | Сам факт. |
| `activity` | соседние отрезки «что делал» одного «где был», по порядку | Эти отрезки и все события в них. |
| `place` | соседние отрезки «где был», по порядку | Эти отрезки, все их «что делал» и все события. |

Все `ids` — элементы этого же персонажа. В редакторе цель выбирается на таймлайне: выделить элемент или диапазон и нажать «Прикрыть легендой».

#### 2.5.2. Легенда (`legend`) и события внутри

| `target.type` | `legend` | Смысл |
|---|---|---|
| `event`, `fact` | `{ "text" }` или `{ "hide": true }` | Подменить событие или факт другим или скрыть его. Подменённое событие получает время исходного. |
| `activity` | `{ "text" }` | Чем, по словам персонажа, он занимался на всём промежутке прикрытых отрезков. |
| `place` | `{ "place", "text" }` | Где был и что делал на всём промежутке. «Что делал» подменяется вместе с местом. |

В любую легенду, кроме `{ "hide": true }`, можно добавить `details` — подробности того, что персонаж рассказывает. В любую легенду, включая скрывающую, можно добавить `weak_spots` (§2.4.1). У подмены события в `replacements` тоже может быть `details`: `{ "event_id", "text", "details" }`.

У целей `activity` и `place` событие охвата остаётся правдой, скрыто или подменено: подменённые перечислены в `replacements`, остальные следуют `events_default`. Новое событие внутри прикрытого отрезка просто получает судьбу по умолчанию. В редакторе — список событий охвата с выбором «как есть / скрыть / заменить на…».

**Тексты записей блокнота** собираются из полей: отрезок — `{from}–{to}: {place или text}`, событие — `{time}: {text}`, факт — `{text}`. Легенды и подмены — так же; у легенды `place` — `{from}–{to}: {place} — {text}`, а `from`–`to` легенды — от начала первого до конца последнего прикрытого отрезка.

#### 2.5.3. Замок (`lock`)

Условие (§1) из двух видов условий:

```json
{ "evidence": "ev_pass_log", "require_show": true }
{ "statement": "oleg_e_saw_anna" }
```

- **Улика** — уже открытая игроком. `require_show` (по умолчанию `false`) — галочка «требовать предъявить»: устного упоминания мало, персонаж требует показать улику, засчитывается только предъявление через интерфейс (с доски или в несостыковке).
- **Показание** — слова **другого** персонажа, уже записанные в блокнот (даже опровергнутые). Засчитываются и кнопкой «Пересказать», и устно.

Выполненные условия запоминаются по ключам `evidence:<id>` и `statement:<id>`.

#### 2.5.4. Вложенность, каскад и картина мира

- Слой **активен**, если он не снят, а все слои над ним сняты. Верхние слои активны с начала дела.
- Охват подслоя лежит внутри охвата родителя (совпадение — вторая легенда на то же самое). Охваты пересекаются только у предка и потомка, поэтому элемент прикрыт не больше чем одним активным слоем.
- Под снятым слоем открываются его подслои, а там, где подслоёв нет, — правда.
- Условия засчитываются **заранее**, в том числе нижним, ещё неактивным слоям. Если после снятия верхнего слоя замок открывшегося слоя уже выполнен, он снимается сразу, в том же ходе (каскад, §4.3). Персонаж никогда не остаётся на уже опровергнутой легенде.

**Правда под двумя разными легендами.** Бывает, что нижняя правда должна открыться, только когда сняты две разные верхние лжи (A и B). Её кладут подслоем под одну из них (под A), а в её замок добавляют условия замка B (если у B несколько способов, каждый способ нижнего слоя комбинируется с каждым способом B). Тогда она откроется не раньше, чем сняты обе лжи. Нового вида условий не нужно.

**Картина мира** для ИИ-актёра собирается после каскада: элемент, не прикрытый активным слоем, виден как правда, прикрытый — как велит легенда (§2.5.2), к каждой активной легенде добавляются её `lie_motive` и `weak_spots`, к каждому видимому элементу — его `details`. Смысловую согласованность соседних слоёв обеспечивает автор.

### 2.6. Улика (`evidence[]`)

| Поле | Тип | Что это |
|---|---|---|
| `id` | id | Идентификатор. |
| `title` | строка | Название на доске и в уведомлениях. |
| `type` | `document` \| `item` \| `place` | Документ, предмет или место/осмотр. |
| `short_description` | строка | Строка в списке на доске. Вместе с `title` — подсказка служебной проверке, указал ли персонаж на закрытую улику. |
| `full_text` | строка | Полный текст: читает игрок, видит ИИ после предъявления. |
| `open_condition` | условие из id персонажей или `null` | `null` — стартовая улика. Иначе улика открывается, когда персонажи прямо указали на неё в диалоге: `[["vera"], ["oleg"]]` — хватит любого из двух, `[["vera", "oleg"]]` — нужны оба (указания копятся между ходами и персонажами). |

Снятие слоя улику не открывает, её открывает только `open_condition`.

### 2.7. Конфликты для несостыковок (`conflicts[]`)

| Поле | Тип | Что это |
|---|---|---|
| `id` | id | Идентификатор конфликта и собранной несостыковки. |
| `a`, `b` | id показания или улики | Стороны: показание + показание разных персонажей или показание + улика. Вид определяется по id. |
| `description` | строка | Пояснение, которое игрок видит в блокноте после сборки. |

Порядок сторон не важен.

### 2.8. Финал (`finale`)

| Поле | Тип | Что это |
|---|---|---|
| `killer_id` | id персонажа | Убийца. Для выбора предлагаются все персонажи. |
| `motive_options` | массив `{ "text", "correct" }` | Варианты мотива, не меньше двух, ровно у одного `correct: true` (по умолчанию `false`). |
| `method_options` | массив `{ "text", "correct" }` | Варианты способа, правила те же. |
| `final_text` | строка | Развязка на экране победы. ИИ её не видит. |

Верно выбранный при любой попытке пункт отмечается навсегда; дело раскрыто, когда отмечены все три.

## 3. Идентификаторы и показания

### 3.1. Идентификаторы

- **id генерирует редактор; автор их никогда не видит и не вводит.** В редакторе показываются тексты, ссылки выбираются из списков. Читаемые id в примерах — только для наглядности.
- Формат `^[a-z][a-z0-9_]*$`. id уникальны на всё дело во всех коллекциях: персонажи, отрезки, события, факты, слои, улики, конфликты.
- id не меняется при правке текстов.

### 3.2. Показания (statement)

**Показание** — единица, которую персонаж может произнести и которая может попасть в блокнот. Источники:

| Источник | id показания |
|---|---|
| отрезок «где был», «что делал», событие, факт | id элемента |
| легенда слоя (кроме `{ "hide": true }`) | id слоя |
| подмена события в `replacements` | `<id слоя>/<id события>`, например `anna_l_fall/anna_e_blow` |

Id подмены собирается сам (`/` в обычных id не встречается). Каждое показание принадлежит одному персонажу; при загрузке код строит таблицу «показание → персонаж, текст, слой».

**Важность для блокнота.** Показание записывается в блокнот, если у элемента `notebook_important: true`, если это легенда или подмена, или если на него ссылается замок или конфликт. В последнем случае важность включается автоматически, и редактор не даёт её снять.

## 4. Состояние партии

Хранится только меняющееся; данные дела и всё выводимое не дублируются.

### 4.1. Корень состояния

| Поле | Тип | Что это |
|---|---|---|
| `current_character_id` | id персонажа | С кем сейчас разговор. |
| `opened_evidence` | массив id улик | Открытые улики в порядке открытия, стартовые — сразу. |
| `evidence_mentions` | `{ evidence_id: [character_id] }` | Кто уже указал на ещё закрытую улику (для способов из нескольких персонажей). |
| `heard_statements` | массив id показаний | Блокнот: записанные показания в порядке записи. Группировка по персонажам берётся из таблицы показаний. |
| `inconsistencies` | массив id конфликтов | Собранные несостыковки в порядке сборки. |
| `characters` | `{ character_id: объект }` | Состояние персонажей, §4.2. |
| `accusation` | `{ "killer_found", "motive_found", "method_found" }` | Флаги только включаются. |
| `badges` | `{ "evidence": [id], "notebook": [id] }` | Индикаторы нового: непросмотренные улики и новые записи блокнота. Очищаются при открытии вкладки (или карточки улики). |

Статус дела вычисляется: нет сохранения — «не начато», все три флага обвинения включены — «раскрыто» (тогда показывается `final_text`), иначе — «в процессе».

**Блокнот.** Запись появляется один раз, когда служебная проверка отметила, что персонаж озвучил важное показание своей текущей картины мира, и не удаляется. Опровергнута она, если это легенда или подмена снятого слоя (вычисляется из `removed_layers`); для замков и пересказа годится и опровергнутая. **Несостыковка:** если выбранная игроком пара (записи и/или открытые улики) есть в `conflicts`, её id добавляется в `inconsistencies`; иначе мягкое сообщение без изменений.

### 4.2. Состояние персонажа

| Поле | Тип | Что это |
|---|---|---|
| `greeted` | bool | Первая фраза уже прозвучала. |
| `emotion` | эмоция | Текущая эмоция, в начале — `starting_emotion`. |
| `removed_layers` | массив id слоёв | Снятые слои в порядке снятия. Из него вычисляются активные слои. |
| `lock_progress` | `{ layer_id: [ключи] }` | Выполненные условия каждого ещё не снятого слоя, и активного, и нижнего. Не сбрасывается при смене персонажа. ИИ его не видит. |
| `memory` | объект | Память о диалоге. Её поля описаны в `AI_PROTOCOL_V2.md`. |
| `log` | массив | Лента диалога для экрана: реплики (с эмоцией и ремаркой) и служебные уведомления. В промпт не идёт. |

### 4.3. Предъявление, засчитывание и каскад

Когда игрок что-то предъявляет текущему персонажу:

1. **Какие ключи выполнены:**
   - улика через интерфейс → `evidence:<id>`;
   - улика устно (подтвердил судья) → `evidence:<id>` только для условий без `require_show`; иначе в событие хода идёт сигнал «потребовать показать улику»;
   - пересказ показания, кнопкой или устно → `statement:<id>`;
   - несостыковка → ключи обеих сторон (улика в ней считается предъявленной через интерфейс).
   Устно засчитываются только открытые улики и записанные показания.
2. **Засчитывание заранее.** Ключи добавляются в `lock_progress` каждого ещё не снятого слоя этого персонажа, в замке которого они есть, — и активного, и нижнего.
3. **Каскад.** Пока есть активный слой, у которого хотя бы один способ замка выполнен целиком:
   - слой добавляется в `removed_layers`;
   - в память пишется снятая легенда и ключи, которыми её поймали;
   - его подслои становятся активными, и проверка повторяется.
4. **Ответ.** Только после каскада код собирает картину мира (§2.5.4) и событие хода: что предъявлено и какие слои сняты. Актёр видит итоговую картину, как будто промежуточных слоёв не было.

Уведомления ленты пишутся в `log` текущего персонажа.

## 6. Проверки

### 6.1. Загрузчик игры: только структура

Загрузчик проверяет, что дело соответствует правилам §1–3, и при ошибке не открывает его, показывая список ошибок с названиями элементов:
- формат: `schema_version` = `2`, обязательные поля и типы, допустимые значения, формат и уникальность id;
- ссылки: каждая ведёт на существующий элемент нужного вида (`target.ids` и `replacements` — на элементы своего персонажа и охвата, показание в замке — другого персонажа и не скрывающая легенда, `relationships` — не на себя и без повторов);
- время: формат `HH:MM` или `N HH:MM` (`N` ≥ 1), `start` < `end`; отрезки внутри окна и своего родителя, по порядку, без пересечений, `from` < `to`; события внутри своего «что делал». Всё сравнивается с учётом дня;
- слои: цель по правилам §2.5.1, форма легенды по §2.5.2, охват подслоя внутри родителя, пересечения только «предок — потомок», нет подслоёв под `lock: null`;
- условия: способы и условия не пустые, `require_show` только у улик;
- есть стартовая улика; у конфликта хотя бы одно показание, два показания — разных персонажей, пары не повторяются; в вариантах финала не меньше двух и ровно один верный.

### 6.2. Редактор: проходимость и подсказки

Перед тестовым прохождением и публикацией; проблема показывается у нужного элемента, ошибки блокируют публикацию.

- **Проходимость (ошибка).** Редактор моделирует прохождение: все улики открыты, доступны все показания текущих картин мира. Ключи засчитываются всем ещё не снятым слоям, потом слои каскадом снимаются, открывшиеся показания добавляются, и так по кругу, пока что-то меняется. Каждый слой с замком должен в итоге сняться, а каждое показание из конфликта — стать доступным. Если нет, ошибка «замок недостижим»: условие лежит под неснимаемым слоем, ждёт показание, которое откроется только после этого же слоя, или два замка ждут друг друга.
- **Подсказки (предупреждения):** у персонажа нет первой фразы; открываемая улика не используется ни в одном замке и конфликте; у персонажа нет ни одного важного показания.

## 7. Фрагмент примера

Полное дело «Ночь в библиотеке» — в [examples/library_night.json](examples/library_night.json). Ниже — алиби Анны (снимается показанием Олега + показанным журналом пропусков) и под ним легенда о падении (снимается пресс-папье). Если пресс-папье показали до снятия алиби, обе легенды снимутся в одном ходе.

```json
{
  "id": "anna_l_alibi",
  "target": { "type": "place", "ids": ["anna_p_archive"] },
  "legend": {
    "place": "читальный зал",
    "text": "дочитывала главу, в архив не заходила, в 21:00 ушла",
    "details": "Называет настоящую книгу, с которой работала. «Ушла примерно в девять, может, чуть позже». Про Гурова: «Видела днём мельком, кивнули друг другу».",
    "weak_spots": "Про 20:30–21:00 рассказывает слишком гладко, как заученное. Не может толком сказать, какую главу «дочитывала». Когда речь заходит об архиве, переводит разговор на диссертацию."
  },
  "lie_motive": "Архив — место убийства; признать, что была там, значит стать главной подозреваемой.",
  "lock": [[{ "statement": "oleg_e_saw_anna" }, { "evidence": "ev_pass_log", "require_show": true }]],
  "sub_layers": [
    {
      "id": "anna_l_fall",
      "target": { "type": "activity", "ids": ["anna_a_quarrel"] },
      "legend": { "text": "зашла к Гурову спросить про книги, он оступился и ударился о стеллаж, она испугалась и убежала" },
      "replacements": [
        { "event_id": "anna_e_quarrel", "text": "Гуров накричал на неё из-за просроченных книг" },
        { "event_id": "anna_e_blow", "text": "Гуров оступился и ударился затылком о стеллаж" }
```
