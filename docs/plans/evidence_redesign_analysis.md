# Улики, противоречия, «предъявить против показания»: разбор предложения ChatGPT (2026-11-25)

Только анализ. Код, `case_editor_plan.md` и ветки не менялись. Сверено с `main` (ea6f443; код в ветке `docs/agents-md` тот же) и с планом (607 строк, ветка `docs/agents-md`, 13f404c).

## 1. Как работает сейчас

**Показания («statements») уже есть, только называются «журнал услышанного».**
- Модель в каждом ответе заполняет поле `stated`: ключи `k1…` из блока «ЧТО ТЫ МОЖЕШЬ СКАЗАТЬ», которые прозвучали в реплике. `ResponseValidator` проверяет, что ключ взят из пакета и что форма подходит к его режиму. Числа из реплики он ещё и сам дописывает через `_auto_state`. Потом `Game._turn` → `RulesEngine.register_statements` → `_add_heard`.
- Хранение: `GameState.heard[] = {agent_id, fact_id, form, turn}`, где form — `lie` / `basic` / `full`. Пара `fact_id + form` уникальна (`_journal_has`), и факт принадлежит одному персонажу. Значит, у каждого показания уже есть естественный id `fact_id|form`, только явно он не записан. Сохраняется в сейве целиком.
- Показ: `Notebook.entries()` → экран «Блокнот» (`ui/screens/notebook.gd`). Строка: «Имя, ход N: «текст»». Текст берётся из дела (`lie_text` / `content_basic` / `content_full`), это не дословная реплика. Строки только для чтения, кнопок на них нет. Отдельная вкладка показывает найденные противоречия.

**Кто решает, что ложь сломана: движок, а не ИИ.**
- *Показ улики кнопкой*: `Game.present` → `RulesEngine.present_evidence` → `_present` пишет `state.shown[e] += agent` → `_resolve` → `_pass_facts` → `_lie_breaks`. Ложь ломается, если у неё в `breaks_lie_on` есть `evidence`, улика стоит в её `related_evidence_ids`, улику показали **владельцу** лжи и выполнены `requires_broken_lies`. Всё это происходит **до** запроса к ИИ, и ИИ получает уже открытую правду в пакете. Неподходящая улика просто попадает к этому персонажу в «УЛИКИ, КОТОРЫЕ ТЕБЕ ПОКАЗАЛИ», а ложь остаётся [ЛОЖЬ].
- *Голосом или текстом*: ИИ только **классифицирует** реплику игрока, выбирая номер из закрытого списка «ВЫБОР» (`TurnOptions`). Например: «игрок называет содержание улики X» (`present`) или «игрок говорит, что Павел сказал «…»» (`cite`). Последствия считает код (`TurnOptions.plan` → `RulesEngine.commit_plan`). Затем ход перезапускается с запиской «Признай только это: …» (`_admit_note`).
- *Противоречие*: `_pass_contradictions` регистрирует его, когда обе стороны есть в журнале (`state.contradictions`). **Само по себе оно ложь не ломает**: только записывает в блокнот и даёт давление, которое не используется. Ложь ломается, когда игрок **пересказывает лжецу** правдивые слова другого (`cite` → `break_lies`).
- Защита от раскрытия раньше времени: правило 1 промпта (только факты пакета); закрытая правда в пакет не попадает вообще; `ResponseValidator._leaks` ловит в реплике основы слов из закрытой или скрытой правды; форма `stated` проверяется по режиму пакета; `requires_broken_lies` охраняется в `_lie_breaks` (и по плану 9.2 ещё в `commit_plan` / `_cite_ok` / `_present_grants`).

**Поля, о которых спрашивал ChatGPT:**
| Поле | Что делает сейчас |
|---|---|
| `fact.breaks_lie_on` | Чем ломается ложь: `evidence` / `contradiction` (`pressure` не используется). По плану (§6) редактор вычисляет его сам. |
| `fact.related_evidence_ids` | **Главная связь** «показание ↔ улика». По ней движок решает слом и полное признание (`requires_evidence`). |
| `evidence.related_fact_ids` | Обратная связь. В игре **не читается**, редактор вычисляет её сам (§6). |
| `evidence.related_agent_ids` | Только давление при показе (не используется); по плану — значок «новое». На слом не влияет. |
| условие `inconsistency_created` | Валидатор его знает, но `Conditions.evaluate` всегда возвращает «нет». Редактор его не предлагает (§5, §7). |
| Передача контекста NPC | Полный текст показанной улики получает **только тот персонаж, которому её показали** (`_shown_block`). Остальные видят только названия открытых улик. В блокнот в промпте идут чужие показания (`_notebook_block`). |

## 2. Что из предложения уже есть в плане и коде

| Идея ChatGPT | Статус |
|---|---|
| Противоречие не ломает ложь само | **Уже так.** Только запись в блокнот; слом — пересказом лжецу правды другого. |
| Опровержение = прямая связь «улика ↔ утверждение», ложь ломает только оно | **Уже так**, связь задаётся «Связанными уликами» показания. Решает движок. |
| ИИ не решает, доказана ли ложь | **Уже так.** ИИ только выбирает номер «что сказал игрок»; при показе кнопкой ИИ вообще не участвует в решении. |
| Зацепка: при показе контекст получает только этот персонаж | **Уже так** (`_shown_block`). |
| Зацепка открывает новое направление | **Уже так**: условия появления улик (`evidence_mentioned`, `evidence_shown`, `lie_broken`, `dialogue_with`, И/ИЛИ) и «Правда, полностью только после показа улики» (например `fact_roman_log` ← журнал охраны). |
| Три состояния: найдено / показано X / X признал | **Уже раздельно**: `unlocked_evidence` / `shown[e]` / `broken_lies` + `fact_levels` + `heard`. |
| Можно показать неподходящую улику | **Уже можно** кнопкой любому персонажу; ложь не ломается. |
| Не допустить двойного слома | **Уже есть**: `broken_lies.has`, `_shown_to` (повторный показ той же улики тому же персонажу ничего не делает). |
| Каждое показание отдельно идентифицировано | **Почти**: уникальная пара `fact_id|form`, но в интерфейсе нет выбора. |
| **Предъявить улику против конкретного показания из журнала** | **Нет.** Новое. |
| **ИИ получает явный вердикт движка** («не опровергает — оспаривай/объясняй») | **Частично**: при сломе есть явная записка «признай», при «мимо» прямого вердикта нет, ИИ просто видит, что ложь осталась [ЛОЖЬ]. |
| **Итог предъявления в журнале и сейве** | **Нет.** В ленте есть «Вы показали: …», а 9.17 / часть 2 сохраняет события ленты. Отдельного журнала «что против чего показали и чем кончилось» нет. |
| Противоречие «показание ↔ известный факт» | По сути это и есть «ложь со связанной уликой». Отдельного автоматического обнаружения нет, и **заводить его не надо** (см. §3). |

Вывод: из трёх типов ChatGPT два с половиной уже работают ровно так, как он описывает. По-настоящему нового три вещи: выбор показания в журнале, явный вердикт для ИИ и журнал предъявлений.

## 3. Совместимость и конфликты

1. **Строгое «ломает только улика, нацеленная на это показание» сломает дело.**
   - 4 лжи после переразбивки (§10) ломаются только пересказом по противоречию (`fact_irina_affair`, `fact_arkady_humiliation`, `fact_arkady_mira_blame`, `fact_mira_arkady`), и ещё у 5 пересказ — второй путь. Если понимать «опровергает только улика» буквально, их нельзя будет разоблачить. Пересказ правды другого персонажа надо считать опровержением **показанием**, как сейчас.
   - Признание Аркадия (`fact_arkady_panic`) ломается тем же ножом, что и «нож», и само, как только сломана «встреча» (9.2, §10). Если слом зависит от выбранного показания, эта цепочка перестанет работать.
2. **Голосовая игра.** На планшете игра идёт в первую очередь голосом. Голосом нельзя «выбрать строку журнала». Если завести голосовые варианты «улика X против показания Y», список «ВЫБОР» вырастет до N×M строк: промпт раздуется, модель будет путаться. Поэтому нацеливание должно быть **дополнительным** способом (точность и контекст), а не обязательным условием слома.
3. **Слово «Зацепки» уже занято.** В плане (§4 «Блок „Противоречит показанию…“», §12) «Зацепки» — это отложенные противоречия «правда–правда». Если брать «Зацепку» в смысле ChatGPT, отложенный пункт надо переименовать (например, «Нестыковки правда–правда»).
4. **Автоматическое «показание противоречит улике» — спойлер.** Если блокнот сам пишет «слова Аркадия расходятся с журналом охраны», игроку подсказывают, какую улику кому показать. Не делать.
5. **Сохранения.** Новое поле сейва необязательное, старые загружаются. Файл дела **не меняется**, значит хеш тот же и сохранения не сбрасываются (1а-1 их и так сбрасывает).
6. **Редактор (часть 4).** Новых полей для автора не нужно: вердикт выводится из уже существующих «Связанных улик», `requires_evidence` и `requires_broken_lies`. Ручных связей «показание → факт → улика» нет, `breaks_lie_on` по-прежнему вычисляется сам.
7. **Нужен ли 4-й тип?** Нет. Противоречие (сверка двух показаний), опровержение (улика или пересказ ломает ложь) и зацепка (улика открывает новое) покрывают всё. Вердикт «пока держится» — это состояние опровержения, а не отдельный тип.

## 4. Рекомендуемая минимальная схема

**Принцип: «предъявить против показания» = тот же показ улики персонажу + выбранная цель + явный вердикт в промпте + запись в журнал. Правило слома не меняется.** Показ улики персонажу по-прежнему ломает все его несломанные лжи, связанные с этой уликой (иначе ломаются голос и цепочки). От цели зависят только текст вердикта для ИИ и запись в журнале.

**Данные дела:** без изменений.
- Показание = факт персонажа. id показания в журнале = `fact_id|form` (вычисляется, в файл дела не пишется).
- Связи «показание → ложь → улики» = `fact.related_evidence_ids` + `breaks_lie_on` (их ставит редактор). `evidence.related_fact_ids` остаётся производным и движком не читается.

**Состояние (`GameState`):** одно новое необязательное поле.
```
confrontations: Array[Dictionary]   # старые сейвы: []
  {turn, agent_id, statement: "fact_id|form", evidence_id, verdict}
```

**Вердикт** (`RulesEngine.confront(agent_id, statement_id, evidence_id)`). Порядок проверок:
1. Улика не открыта, показание не этого персонажа или его нет в журнале → отказ (интерфейс такого не даёт).
2. Та же пара «показание + улика» уже была → `repeat`: эффекта нет, ход идёт как обычный вопрос.
3. Показание — ложь (`form=lie`), ложь не сломана, улика в `related_evidence_ids`, в `breaks_lie_on` есть `evidence`:
   - `requires_broken_lies` выполнены → **`refuted`** (ложь сломана, признание полное, потому что улика показана);
   - не выполнены → **`holds`** («пока держится»). Улика запомнена как показанная, и ложь сломается сама, когда будут сломаны нужные (это нынешнее поведение 9.2).
4. Ложь уже сломана, но была только «неполное признание» (сломана пересказом, `requires_evidence`), а улика связанная → **`completed`** (полное признание).
5. Ложь уже сломана полностью → **`already`**.
6. Всё остальное → **`not_refuted`**. Сюда же попадает правдивое показание: игроку **не сообщается**, что это правда, иначе это подсказка.
7. Побочно: если эта же улика ломает **другую** ложь этого персонажа, она ломается (как при обычном показе). Вердикт по выбранному показанию остаётся своим, а в журнал пишется событие «разоблачено также: …».

Реализация — тонкая обёртка: снять `broken_lies` / `fact_levels` до показа → `_present` + `_resolve` → сравнить для цели. Новой логики слома нет.

**Зацепка:** новых полей не нужно. Зацепка — это улика, которая (а) открывает другие улики через условия, (б) открывает «Правду, полностью только после показа» или (в) просто показывается персонажу, который её не связан, и тот реагирует по характеру, зная только её текст. Опциональное поле «что персонаж знает об этой улике» (личная реакция на зацепку) предлагаю **отложить** (см. вопросы).

**Противоречие:** оставить как есть: обе стороны услышаны → запись в блокнот; ломает только пересказ лжецу. Одна дешёвая доработка на выбор: включить условие `inconsistency_created` (`state.contradictions.has(id)`, 1–3 строки + блок в редакторе). Тогда найденное противоречие сможет **открыть зацепку**, то есть новую улику. Это ровно «противоречие выявляет, но не доказывает».

## 5. Интерфейс

- **Блокнот → «Записи».** У строки лжи персонажа (несломанной) кнопка «Предъявить улику». Она открывает доску улик, игрок выбирает любую открытую. Дальше экран переходит на допрос этого персонажа, и ход уходит сам. Можно добавить строку голосом или текстом, как в нынешнем `_confirm_hint`. На строках правды кнопка тоже есть: игрок не должен по её отсутствию понять, что это правда. Сломанная ложь помечена «✓ разоблачено», без кнопки.
- В ленте: «Вы: предъявили «Журнал охраны» против слов «Ушёл домой в 00:30»». После ответа — значок итога: «Опровергнуто» / «Пока держится» / «Не опровергает» / «Уже признано».
- В блокноте новая вкладка или фильтр «Предъявления» (история из `confrontations`).
- **Голос не меняется:** «Вот журнал охраны, а вы говорили, что ушли в 00:30» идёт по нынешнему пути `present` / кнопка подсказки. Движок ломает все связанные лжи персонажа, как сейчас. Новых голосовых вариантов в «ВЫБОРЕ» нет, промпт не растёт.

## 6. Изменения по модулям

| Модуль | Что |
|---|---|
| `RulesEngine` | `confront()` (вердикт по схеме выше, через `_present` / `_resolve`); запись в `state.confrontations`; событие `confronted`. |
| `GameState` | поле `confrontations` в `to_dict` / `from_dict` (нет → `[]`). |
| `Conditions` | (по выбору, вопрос 4) `inconsistency_created` → `state.contradictions.has(contradiction_id)`. |
| `TurnOptions` | без изменений. Голосовой путь остаётся `present` / `cite`. |
| `PromptBuilder` | для хода-предъявления — строка события **только этому персонажу**: «Следователь предъявляет улику «X» против твоих слов «<lie_text>». Итог проверки: …». При `not_refuted` / `holds` / `already`: «Это тебя не опровергает. Держись своей версии, можешь оспорить, объяснить или уйти от ответа. Ничего сверх блока ЧТО ТЫ МОЖЕШЬ СКАЗАТЬ не признавай». При `refuted` / `completed` используется нынешний пакет с [ПРАВДА] плюс «признай это». Текст чужих фактов и закрытой правды сюда не попадает. |
| `Game` (autoload) | `confront(agent_id, statement_id, evidence_id, text)` → `_turn` с этой строкой события. Снимок до хода (9.9) охватывает и `confrontations`. |
| `Notebook` | `entries()` отдаёт `statement_id` и `broken`; новая `confrontations()`. Ветки `partial_truth` уже удаляются в 9.1. |
| `ui/screens/notebook.gd`, `interrogation.gd` | кнопка у строки, выбор улики, переход к персонажу, значок итога в ленте. |
| `CaseData`, `CaseLoader`, `CaseValidator`, редактор | без изменений. По вопросу 4 — блок «После найденного противоречия» в «Когда появляется» и снятие ошибки §7 для `inconsistency_created`. Текст «?» у «Связанных улик» дополнить: «…и предъявление её против этого показания». |

## 7. Тесты

Юнит (`test_rules_engine`, `test_prompt_builder`, `test_turn_flow`):
- вердикты: `refuted` (`журнал → встреча` Аркадия), `holds` (нож → признание при несломанной «встрече»; потом ломается «встреча» → признание сломалось само), `completed` (долг Аркадия сломан пересказом → фин. документы → полное), `already`, `not_refuted` (чужая улика; правдивое показание даёт тот же вердикт, что и мимо), `repeat` (никакого эффекта);
- побочный слом: нож против «встречи» ломает «нож», вердикт по цели `not_refuted`, в журнале «разоблачено также»;
- двойной слом невозможен; `broken_lies` без дублей;
- сейв: `confrontations` переживает запись и чтение; старый сейв без поля загружается;
- снимок посреди хода (9.9) откатывает и `confrontations`;
- **анти-раскрытие (детерминированно, по тексту промпта):** после `not_refuted` / `holds` в промпте нет `content_basic` / `content_full` закрытых фактов этого персонажа, ложь осталась [ЛОЖЬ]; промпты **других** персонажей не содержат ни строки события, ни `full_text` улики, если её им не показывали; в строке события нет текста чужих фактов;
- `ResponseValidator`: ответ, где после `not_refuted` звучит основа слов закрытой правды, ловится `_leaks` и уходит в повтор; `stated` с формой `full` для закрытого факта отклоняется (регресс существующего);
- голосовой путь: регресс `present` / `cite` без изменений; список «ВЫБОР» не вырос.

Бокс (тестовый ключ, меньше 10 запросов в минуту, 4–6 ходов): неподходящая улика против лжи → персонаж не признаётся и держит версию; подходящая → признаётся ровно в «Что он расскажет»; `holds` → не признаётся; в логах нет ключей и промпта.

- Редактор (часть 4) почти не затрагивается: только «?»-текст и, по вопросу 4, блок условия.

## 9. Вопросы к Тимуру (с рекомендацией)

1. **Нацеливание — точность или условие?** Если улика ломает другую ложь этого же персонажа, а не выбранную, ломать её? *Рекомендую: да.* Нацеливание даёт контекст и журнал, правило слома прежнее. Иначе ломаются голос и цепочка признания Аркадия.
2. **Показывать ли игроку «Пока держится»** (улика правильная, но рано)? *Рекомендую: да.* Голосом играть и так трудно, а это честная подсказка «копай дальше». Вариант строже: показывать как «Не опровергает».
3. **Штраф за перебор улик** (показывать всё подряд всем)? *Рекомендую: без штрафа.* Каждая попытка и так стоит ход ИИ. Счёт неудачных попыток можно вести только в журнале.
4. **Включить условие «После найденного противоречия»** (`inconsistency_created`), чтобы противоречие могло открыть зацепку-улику? *Рекомендую: да.* Дёшево и ровно в духе «противоречие выявляет». Во встроенном деле пока не используется.
5. **Личная реакция персонажа на зацепку** (поле улики «что знает об этом персонаж X»)? *Рекомендую: отложить* в §12. Сейчас персонаж видит текст показанной улики и реагирует по характеру, нового поля в редакторе это не требует.
6. **Переименовать отложенные «Зацепки» (правда–правда)** в «Нестыковки правда–правда», чтобы слово «Зацепка» означало улику, которая открывает новое? *Рекомендую: да* (одна правка текста плана).
7. **Отдельный PR 1в или вклеить в 1б + часть 2?** *Рекомендую: отдельный 1в* после 1б (меньше риска, проверка в один заход).
8. **Кнопка «Предъявить» у правдивых показаний?** *Рекомендую: да, с тем же вердиктом «Не опровергает»*, чтобы интерфейс не выдавал, где правда.

## 10. Где предложение вредит или раздувает объём (не брать)

- Обязательный выбор «показание + улика» для слома: ломает голосовую игру и цепочки.
- Голосовые варианты «улика × показание» в «ВЫБОРЕ»: раздувает промпт, модель путается.
- Отдельная сущность «statement» с ручными связями к фактам, лжи и уликам: всё уже выводится из `fact_id|form` и «Связанных улик».
- Отдельный тип «Зацепка» с новыми полями и состояниями: уже покрыт условиями появления и «Правдой после показа».
- Автоматическое «показание противоречит улике» в блокноте: прямой спойлер.
- Вердикт, который решает ИИ («доказано / не доказано»): сейчас решает движок, так и оставить.
