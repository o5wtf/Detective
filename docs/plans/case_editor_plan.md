## 0. Цель и принципы
- **Цель:** внутри игры на планшете создать или поправить полное дело, которое загружается и проходится. Каждое поле заполняется своим элементом: строкой, многострочным текстом, списком, переключателем, галочками или блоками условий. Id вручную не вводятся, сырой JSON не правится.
- **Где находится:** главное меню → кнопка «Редактор дела». Кнопка видна, когда в настройках включена галочка «Для разработчика» (`ui/screens/settings.gd`, флажок `DeveloperMode`).
- **Формат дела расширяется обратно совместимо.** Новые необязательные поля персонажа (раздел 4) и объект `"editor": {"timeline_text": …}` — шпаргалка автора, которую загрузчик игнорирует. Механика «частей правды» (`partial_truth`) удаляется из движка. У лжи появляется поле `breaks_with` (наборы слома, раздел 4 и 9.35); дело без него читается по `breaks_lie_on` (перевод — 9.35).
- **Всё, чего нет в интерфейсе, сохраняется как есть.** Неизвестные ключи и скрытые поля переносятся без изменений: `starting_fatigue`, `starting_pressure`, `pressure_for_basic/full`, `tags`, `background`, `is_key`, значение `"pressure"` в `breaks_lie_on`, неподдерживаемые условия. Поля, которые редактор вычисляет сам (раздел 6), пересчитываются при каждом сохранении.
- Запись редактора не должна идти только из `CaseData`: текущий `CaseLoader` известные поля копирует, остальные отбрасывает, и иначе незнакомые поля потеряются, а круговой тест (§11, часть 3) не сойдётся.
- **Безопасность:** ключей и секретов нет ни в одном файле и логе редактора (раздел 13).
- **Проверки:** правила `CaseValidator` и правила редактора (раздел 7), понятным русским текстом с кнопкой «Перейти». Ошибки блокируют публикацию, предупреждения нет. Проверка проходимости (симуляция «улика никогда не появится») не делается: проходимость Тимур проверяет игрой сам.
- **Язык.** Сейчас игра только на русском; мультиязычность — отдельный план на потом (раздел 12). Чтобы не плодить новый жёсткий русский, весь **новый** код этого плана берёт язык и языкозависимые строки из одной константы: новый `src/core/game_language.gd` (`class_name GameLanguage`, `const CODE := "ru"` и словарь строк по коду языка, сейчас только `"ru"`). Вводится в PR 9.33 (первый пункт, которому он нужен). Через него идут: новые строки локального STT (9.33), промпт STT (9.25), стандартные междометия (9.30), инструкция для `heard` (9.32), подписи настройки и поля «Ругается» (9.34). Модели Parakeet язык не передаётся (определяет сама). Уже существующие строки (`UiStrings`, `PromptBuilder.RULES`, `Summarizer`, Chirp `ru-RU`, фильтр утечек, `SpeechJunk`) в этом плане не переписываются. Подписи интерфейса редактора и PR 1в (кнопки, вкладки, вердикты) — в `UiStrings`, как остальной интерфейс; новые строки промпта 1в (предъявление, сомнение) — рядом с `PromptBuilder.RULES`. В `GameLanguage` идёт только перечисленное выше.
- **Подсказки:** в каждом текстовом поле серый пример, который исчезает при вводе. У списков, переключателей и блоков стоит значок «?»: по нажатию появляется всплывающий блок (не стандартная подсказка Godot, она на касание не работает). Примеры зашиты в редактор, взяты из «Дождя над Тенью» и в таблицах ниже показаны в колонке «Пример».
- **Планшет:**
  - поле в фокусе прокручивается так, чтобы клавиатура его не закрывала (как в `ui/screens/investigation.gd`);
  - длинный текст можно открыть на весь экран;
  - кнопка «Назад» Android закрывает открытую шторку, затем возвращает на предыдущий экран, затем в меню, и не закрывает игру сразу; в меню — подтверждение «Выйти из игры?»; в редакторе «Назад» сразу записывает черновик, без вопроса; если запись не удалась — окно «Не удалось сохранить» с кнопками «Повторить» и «Выйти без сохранения» (раздел 9.15);
  - персонажи, показания и улики переставляются кнопками ↑↓. Порядок важен: это порядок каскада раскрытия и списка подозреваемых, а первый в списке персонаж — стартовый.

## 1. Выбор дела и сохранения
- **Экран «Выбор дела»** в главном меню (вместо одного «Новое дело») показывает опубликованные дела из `user://cases/`. Карточка: название, первые строки брифинга, число персонажей, есть ли сохранение. Кнопки: «Начать», а если есть сохранение — «Продолжить» и «Начать заново». Повреждённое дело помечено «Дело повреждено» и открывает экран ошибок. Если дел нет — пустой экран с кнопкой «Восстановить пример».
- **Имя файла = id дела.** Опубликованное дело лежит в `user://cases/<id>.json`, черновик — в `user://case_drafts/<id>.json`, сохранение — в `user://saves/<id>.json`. Ключ сохранения — поле `id` из JSON (`SaveState.case_id_from_path` читает именно его), поэтому имя файла и `id` всегда совпадают.
- **Встроенный пример.** `res://cases/rain_over_shadow.json` копируется в `user://cases/` побайтно (FileAccess bytes). Его `id` (`test_case_rain_over_shadow_v5`) не меняется, в том числе при переразбивке (раздел 10): сброс старых сохранений делает проверка хеша. Хеш копии при каждом запуске сверяется с хешем оригинала, записанным в момент копирования. Если обновление APK изменило оригинал, копия заменяется новой, а сохранение удаляется по `id` старой копии. Отдельной миграции старых файлов нет. Оригинал в `res://` в списках не показывается.
- **Пример только для просмотра.** В редакторе пример открывается без права правки, с плашкой «Чтобы править — Копировать». Черновика и резервной копии у примера не бывает, поэтому при его замене ничего, кроме сохранения партии, не теряется.
- **«Восстановить пример»** заново копирует оригинал. Перед этим подтверждение: «Сохранение этого дела будет сброшено».
- **Сохранения** у каждого дела свои (`SaveState`). Совместимость проверяется по SHA-256 байтов опубликованного файла. При несовпадении игра пишет «Дело изменилось. Начните заново» (`UiStrings.SAVE_HASH`).
- **Черновик и опубликованная версия** лежат в разных файлах. Правки и автосохранение пишут только черновик, поэтому сохранение игрока не ломается. «Опубликовать» переписывает опубликованный файл. Если у дела есть сохранение, перед этим предупреждение: «Сохранение этого дела будет сброшено».
- **Копия в «Документы».** При каждой публикации дело дополнительно записывается в общую папку устройства: `Documents/Detective/<id>.json` (`OS.get_system_dir(OS.SYSTEM_DIR_DOCUMENTS)`). Это страховка на случай удаления игры, не импорт: читать оттуда игра не умеет.
  - Android 11+ (scoped storage): файл, созданный самой игрой, пишется в общую папку без разрешений. `MANAGE_EXTERNAL_STORAGE` не запрашивается. На Android 10 и ниже нужен `WRITE_EXTERNAL_STORAGE` с запросом через `OS.request_permissions()`.
  - После переустановки игры старый файл ей уже не принадлежит, перезапись может не пройти. Тогда файл пишется под именем `<id>_<дата-время>.json`.
  - Любая неудача (нет папки, нет доступа, нет места) **не блокирует публикацию**: дело публикуется, а игра показывает «Копия в «Документы» не записана: <причина>».
  - Работу на планшете Тимура подтверждает только проверка на устройстве.
- **Персонажей** от 2 до любого числа (минимум проверяется при публикации). Списки игры строятся из данных, жёстких лимитов нет.
- `Speaker.reset_for_case()` вызывается и при «Продолжить».

## 2. Вход в редактор
- **«Мои дела»:** все дела с пометкой «Пример (только просмотр)», «Черновик», «Опубликовано» или «Опубликовано, есть неопубликованные правки». Сверху кнопка «Создать новое дело», внизу «Восстановить пример».
- **У каждого дела:**
  - «Открыть» (у примера — просмотр);
  - «Копировать»: новый id дела, название «… (копия)», «(копия 2)» и так далее;
  - «Удалить»: с подтверждением, удаляет черновик, опубликованный файл, резервную копию и сохранение. Копию в «Документах» не трогает.
- **У примера кнопки «Удалить» нет:** вместо неё «Восстановить пример» (раздел 1). Доступны только «Открыть» (просмотр) и «Копировать».
- **Открытие:** все поля заполняются текущими данными из черновика, а если его нет — из опубликованного файла. Разбор идёт через `CaseLoader.parse(raw)` (раздел 9.13).
- **Новое дело** создаётся из шаблона: два пустых персонажа, по одному пустому варианту способа и мотива, `victory_condition: "correct_accusation"`.
- **Три вкладки:** «Общая картина», «Персонажи», «Улики». Внизу каждой — проверки этой вкладки.

Пока набор собран частично, ложь под сомнением: персонаж защищается, но не признаётся» | `breaks_with` | «Журнал охраны» ИЛИ («Павел: закрытие в 01:00» И «Мира: ушла в 00:50») |
| Противоречит показанию… | блоки (ниже) | `contradictions[]` | — |

`breaks_lie_on` в интерфейсе нет: он вычисляется из «Чем можно сломать» (раздел 6), а движок его не читает, если есть `breaks_with`.

**Как работает показание** (текст «?» у раздела):
- **Правда без условий** открыта сразу.
- **Правда с «Полностью — только после показа улики»** закрыта, пока этому персонажу не покажут ЛЮБУЮ из связанных улик.
- **Ложь.** «Всегда врёт» — только ложь. «Может соврать» — ложь или «Оговорка» (если «Полностью — только после показа улики» выключено, «Оговорка» доступна с первого хода). Ложь ломается целиком, когда собран любой набор из «Чем можно сломать»: этому персонажу показаны все улики набора (кнопкой, пересказом содержания или «Предъявить улику» из блокнота, 9.35) и пересказаны все слова других персонажей из набора. Пересказ слов другого сам по себе ложь не ломает, если автор не задал набор из одного этого пересказа. Пока набор собран частично, ложь «под сомнением»: персонаж знает, что ему предъявили и кто это сказал, защищается в своей манере (с учётом отношений: «он на меня наговаривает», «а вы ему верите?») и скрытую правду не выдаёт. Повтор того же пересказа ничего не добавляет. Слова свидетеля не засчитываются, пока у него самого есть несломанная ложь на ту же тему (общая связанная улика, 9.35). После слома персонаж говорит «Что он расскажет». Если включено «Полностью — только после показа улики», а ложь сломана набором без связанной улики, он сначала говорит «Неполное признание», а после показа связанной улики — всё.
- **Правило автора:** если разоблачена подробность, разоблачён и общий факт. Поэтому общий и частный слой одной правды держите в ОДНОМ показании: общее — в «Неполном признании», подробность — в «Что он расскажет», улику-подробность — в «Связанных уликах» с включённым «Полностью — только после показа улики».

**Блок «Противоречит показанию…»**
- Персонаж: список, только ДРУГИЕ персонажи.
- Его показание: список.
- Галочка «Только после его полной правды» (видна всегда, для любого вида выбранного показания).
- Как записать в блокнот: строка, обязательно → `description`. Пример: «Аркадий говорит, что ушёл домой в 00:30, но Павел видел его в клубе после закрытия в 01:00».
- «?»: «Противоречие засчитывается, когда игрок услышал обе стороны: запись в блокнот и, если нужно, условие появления улики «После найденного противоречия». Ложь оно не ломает — для этого „Чем можно сломать“».
- Противоречия, где обе стороны правда («Нестыковки»), отложены. Существующие показываются только для чтения в «Прочих противоречиях».

## 5. Вкладка «Улики»
| Поле | Элемент | JSON | Пример |
|---|---|---|---|
| Название | строка, обязательно; «?»: «Нужны узнаваемые слова — по ним игра понимает, что игрок назвал улику» | `title` | «Журнал охраны» |
| Тип | Место / Предмет / Документ | `type` = `place`/`object`/`document` (при открытии `scene`, `location`, `item` распознаются) | — |
| Подпись на доске улик | строка, обязательно | `short_description` | «Записи выходов из клуба в ночь убийства.» |
| Содержание улики | многострочный, обязательно; «?»: «Читает игрок; знает персонаж, которому улику показали» | `full_text` | «Журнал показывает выход Аркадия в 01:18. Остальные записи неполные.» |
| Касается персонажей | галочки: владельцы связанных показаний отмечены сами и не снимаются, остальных можно добавить; «?»: «При показе у них появляется значок «новое»» | `related_agent_ids` | «Роман, Аркадий» |

«Ключевая» (`is_key`) и «Связана с показаниями» (`related_fact_ids`) в интерфейсе не показываются (раздел 6).

**Когда появляется** — блоки условия → `unlock_condition`:
- «Доступна сразу» → `null`.
- «Персонаж упомянул её»: персонаж и тема (обязательно) → `{type:"evidence_mentioned", agent_id, evidence_id, topic}`. «?»: «Откроется, когда разговор с этим персонажем дважды коснётся темы или игрок прямо спросит». Пример темы: «кто входил и выходил».
- «Сломана ложь…» → `{type:"lie_broken", fact_id}`.
- «После разговора с персонажем» → `{type:"dialogue_with", agent_id}`.
- «После показа другой улики» (+ необязательно «кому») → `{type:"evidence_shown", evidence_id[, agent_id]}`, саму улику выбрать нельзя.
- «После найденного противоречия» (выбор противоречия) → `{type:"inconsistency_created", contradiction_id}` (9.35). «?»: «Откроется, когда игрок услышал обе стороны этого противоречия».
- «И» / «ИЛИ» с вложенностью → `{"AND":[…]}` / `{"OR":[…]}`.
- `pressure_on_agent` редактор не предлагает: `Conditions.evaluate` для него всегда даёт «нет», и улика с таким условием не откроется. То же для `inconsistency_created` без `contradiction_id`. Если они есть в загруженном файле, блок показывается как «Неподдерживаемое условие» (сохраняется как есть) и даёт ошибку (раздел 7). Исключение — когда он стоит внутри «ИЛИ» рядом с другим вариантом.

## 6. Автоматика редактора
- **id** только латиницей, создаются один раз и не меняются при правках: дело, `agent_…`, `fact_…`, `ev_…`, противоречия, варианты. При «Копировать» новый id получает только дело. id нового дела не совпадает ни с одним файлом в `user://cases/` и `user://case_drafts/`.
- **Стартовый персонаж:** `starting_agent_id` при сохранении равен id первого персонажа в списке. Если в загруженном файле указан другой, этот персонаж при открытии ставится первым.
- **`evidence.related_fact_ids`** всегда равен списку показаний, у которых эта улика в «Связанных уликах».
- **`evidence.related_agent_ids`** = владельцы связанных показаний + добавленные вручную. У встроенного дела совпадает у 6 из 7 улик: у «Места преступления» добавится Роман, это принято.
- **`is_key`**: у новой улики `false`, у существующей сохраняется как есть. Правило «ключевая должна быть связана с показанием» убрано (раздел 9.13).
- **Вид противоречия** (`fact_b_form`) ставится сам: сторона b всегда `truth` (игрок услышал от другого любую правду — оговорку, неполное или полное признание), с галочкой «Только после его полной правды» — `truth_full`. Вид показания другого персонажа (правда или ложь) на это не влияет: во встроенном деле `arkady_kitchen`, `mira_knife`, `mira_return` ссылаются на «Может соврать» Павла и Романа именно в форме `truth`. Форма `lie` у стороны b автоматически не ставится никогда; если она есть в загруженном файле, сохраняется как есть. Сторона a — эта ложь, форма `lie`. Блок создаёт или обновляет запись в `contradictions`, удаление блока удаляет запись.
- **`breaks_lie_on`** у лжи вычисляется из `breaks_with`: `"evidence"`, если хоть в одном наборе есть улика, `"contradiction"`, если хоть в одном есть пересказ. Результат — `null`, строка или список без повторов, никогда не `[]`. Если в файле было `"pressure"`, оно сохраняется (движок его не использует). При наличии `breaks_with` движок поле не читает; оно пишется для `tools/validate_case.py` и совместимости. У встроенного дела после PR 1в (наборы раздела 10) вывод совпадает с файлом для всех 20 лжей (у 4 лжей без наборов — `fact_mira_viktor`, `fact_pavel_side`, `fact_alina_affair`, `fact_roman_grudge` — `null`).
- **`breaks_with`** задаёт автор, редактор его не выдумывает. Если в открытом деле поля нет, оно заполняется переводом из `breaks_lie_on` (9.35), показывается автору и при сохранении пишется явно. Пустые наборы в файл не пишутся; лжи без наборов пишется `[]`. Перевод и явная запись `breaks_with`, а также пересчёт `breaks_lie_on` — с части 4. В части 3 показания переносятся из исходного словаря без изменений.
- **Правда:** `is_lie=false`, `lie_type="cannot_lie"`, `lie_text=""`, `breaks_lie_on=null`, `breaks_with` не пишется. Если ложь переключили в правду, её противоречия и наборы удаляются (с предупреждением). Пересказы этого показания в наборах других лжей остаются.
- **`content_basic`:** если пусто, при сохранении туда копируется «Что он расскажет» (это не ошибка). Исключение — «Может соврать»: там поле («Оговорка») обязательно.
- **`victory_condition`** всегда `"correct_accusation"`. Неизвестные ключи и скрытые поля переносятся как есть (раздел 0). `partial_truth` редактор не пишет.
- **Удаление со ссылками:** окно «Используется в N местах: …» с кнопками «Удалить вместе со ссылками» и «Отмена». Ссылки удаляются каскадно. Если после этого:
  - у улики пустое условие появления — ошибка «Улика осталась без условия» с «Перейти»;
  - у показания исчезло «Только после того, как сломана ложь…» — ошибка «Показание лишилось условия “после сломанной лжи”» с «Перейти»;
  - пропал убийца, верный способ или мотив — обычные ошибки.

  Удаление отменяется одним «Отменить».
- **Порядок** (↑↓) сохраняется в файле как есть.
- **Отношения:** пустые фразы в файл не пишутся (ключ персонажа не сохраняется).

## 7. Проверки (русский текст + «Перейти»)
Только статические правила по данным дела, без симуляции прохождения.

**Ошибки (блокируют публикацию)**
- Нет названия или брифинга. Нет персонажей, вариантов способа или мотива. Меньше 2 персонажей.
- Убийца не выбран. Не отмечен верный способ или мотив.
- У персонажа пусто имя, роль, характер или предыстория.
- Эмоция не из списка, неверный пол или имя голоса. Неверное значение «Ругается» (не `never` / `sometimes` / `often`). В отношениях удалённый персонаж или он сам.
- У показания пусто «Что он расскажет». У «Может соврать» пустая «Оговорка». (Пустое «Неполное признание» у остальных не ошибка: при сохранении заполняется из «Что он расскажет», раздел 6.)
- «Полностью — только после показа улики» включено без связанных улик.
- У лжи пустой текст лжи. У правды заполнен текст лжи.
- Ссылка на удалённое показание в «Только после того, как сломана ложь…».
- «Чем можно сломать»: удалённая улика или показание; пересказ показания этого же персонажа; пустой набор; неизвестный вид пункта (только из файла). У «Всегда врёт» нет ни одного набора. Ложь, у которой ни один набор не собрать: простая проверка по данным, без симуляции — все улики считаются доступными, пересказ возможен, если показание — правда, «Оговорка» или ложь, которую саму можно сломать; повторять, пока список не перестанет меняться (это статический перебор по данным, не симуляция партии).
- Противоречие: удалённое показание, форма «Ложь» у правды (только из файла), обе стороны одинаковы, нет текста для блокнота.
- У улики пусто название, тип, подпись или содержание. Ссылка на удалённого персонажа или показание.
- Условие появления: удалённый персонаж, улика или показание; улика ждёт показа самой себя; пустая группа «И»/«ИЛИ»; «Неподдерживаемое условие» (`pressure_on_agent`; `inconsistency_created` без `contradiction_id`), кроме случая внутри «ИЛИ» рядом с другим вариантом; «После найденного противоречия» с удалённым противоречием.
- «Улика осталась без условия». «Показание лишилось условия “после сломанной лжи”» (после удаления, раздел 6).
- Повторяющиеся или пустые id (на случай ручных файлов).

**Предупреждения (не блокируют)**
- «Может соврать» без наборов «Чем можно сломать»: ложь не сломается, прозвучит только «Оговорка».
- Связанная улика лжи не входит ни в один набор: её показ ложь не сломает, только даст полное признание после слома.
- «Оговорка» совпадает с «Что он расскажет».
- Включено «Полностью — только после показа улики», а «Неполное признание» пустое или совпадает с «Что он расскажет»: слом набором без связанной улики сразу выдаст подробность.
- Противоречие между показаниями одного персонажа (только из файла).
- Неподдерживаемое условие внутри «ИЛИ» рядом с другим вариантом.
- Пустое «Как всё было». Персонаж без показаний.
- Улика без «Касается персонажей» и без связанных показаний.
- У способа или мотива только один вариант. В деле нет улик. Ни у одной лжи нет наборов «Чем можно сломать».
- У убийцы нет ни одной лжи.
- В полях «Живого персонажа» есть время (чч:мм) или числа — похоже на факты дела.

Строка: «МАТ: ты материшься свободно, особенно когда зол или тебя давят (блядь, сука, какого хуя, пиздец), без звёздочек и без замены на „блин“, „чёрт“ или „бред“. Не в каждом предложении. Это часть твоей речи, а не нарушение правил.»
   - `safetySettings` не менять (остаются `BLOCK_ONLY_HIGH` по четырём категориям). `ResponseValidator`, фильтр утечек, `SpeechJunk` и TTS не трогать. Оговорка: `_strip_markup` и `SpeechText.clean` удаляют звёздочки и текст между ними; если модель зацензурирует «б***дь», реплика поедет. Поэтому в строке «МАТ» явно «без звёздочек»; при соблюдении этого правки валидатора не нужны.
   - Риск низкий (промпт и настройка; ядро раскрытия не трогается). Тесты: `test_prompt_builder.gd` — галочка выкл. (любой `profanity`) и галочка вкл. + `never`: в системном тексте нет строки «МАТ:» и приписки к манере; вкл. + `sometimes` / `often`: есть своя формулировка и своя приписка, нет чужой; системный текст одного персонажа при той же настройке одинаков от хода к ходу. Настройки: `[dialogue] profanity` переживает `save_value` → `load_current`, нет ключа — `false`. Загрузчик: нет поля — `never`, неизвестное значение — ошибка валидатора. Поле в редакторе (часть 3): круговой тест «Никогда» / «Иногда» / «Часто». На боксе в уже запланированной живой проверке 1б (те же 2–3 хода, отдельных больших прогонов не добавлять; пауза ≥ 7 с, меньше 10 в минуту, тестовый ключ): галочка вкл., Аркадий (`sometimes`) — в реплике есть настоящий мат без звёздочек; галочка выкл. — мата нет.

35. **Предъявление против показания и наборы слома** (отдельный PR 1в сразу после 1б; решения Тимура 2026-11-25, разбор — `evidence_redesign_analysis.md`).
   - **Три вида находок, четвёртого нет.**
     - Противоречие (игрок услышал обе стороны) — только запись в блокнот и условие `inconsistency_created`, ложь оно не ломает.
     - Опровержение — собранный набор из `breaks_with`. Только оно ломает ложь, и решает это движок, не ИИ.
     - Зацепка — улика, которая открывает новое: другие улики через условия появления или «Правду, полностью только после показа». При показе её текст получает только этот персонаж (`_shown_block`, как сейчас).

     Три состояния остаются раздельными: улика открыта (`unlocked_evidence`), показана персонажу (`shown`), персонаж признал (`broken_lies`, `fact_levels`, `heard`). Автоматической отметки «показание расходится с уликой» нет: это подсказка решения. По той же причине в блокноте нет и пометки «под сомнением» (решение Тимура 2026-11-25).
   - **Формат `breaks_with`** (у лжи; у правды не пишется). Список наборов, набор — список пунктов. Все пункты набора нужны вместе («И»), наборы между собой — «ИЛИ». Пункты записаны в синтаксисе `Conditions`, лжеца движок подставляет сам:
     - `{"type":"evidence_shown","evidence_id":…}` — улика показана этому лжецу (кнопкой, пересказом содержания или «Предъявить улику» из блокнота);
     - `{"type":"testimony_retold","fact_id":…[,"form":"truth_full"]}` — игрок пересказал лжецу это показание другого персонажа, услышанное в виде правды (оговорка, неполное или полное признание; с `truth_full` — только полное).

     Пример: `"breaks_with": [[{"type":"evidence_shown","evidence_id":"ev_security_log"}], [{"type":"testimony_retold","fact_id":"fact_pavel_closing"}, {"type":"testimony_retold","fact_id":"fact_mira_leaving"}]]`.

     `RulesEngine` собирает из наборов `{"OR":[{"AND":набор}, …]}` и вызывает `Conditions.evaluate(cond, state, ctx)`. В `ctx` — лжец и список засчитанных пересказов; это новый необязательный параметр, условия появления улик его не используют. Новой архитектуры нет: это тот же движок «И»/«ИЛИ» и тот же построитель блоков в редакторе.

     Если в `ctx` есть лжец, `evidence_shown` без `agent_id` проверяется как показ этому лжецу; `agent_id` в пунктах набора не пишется (из файла — ошибка). `testimony_retold` допустим только в `breaks_with`: в `unlock_condition` — ошибка «неизвестный тип условия». Внутри набора допустимы только `evidence_shown` и `testimony_retold`, без вложенных «И»/«ИЛИ».
   - **Перевод старых дел.** Если `breaks_with` нет, `CaseLoader` строит его так:
     - за каждую связанную улику при `"evidence"` в `breaks_lie_on` — набор из одной этой улики;
     - за каждое противоречие, где эта ложь — сторона `lie`, а другая сторона `truth`/`truth_full`, при `"contradiction"` в `breaks_lie_on` — набор из одного пересказа этой стороны, с её формой;
     - `"pressure"` и `null` наборов не дают.

     Так старое дело играется как раньше (один свидетель ломает), с одним отличием: правило «свидетель, который сам врёт» действует и здесь. Так — пока автор не поменяет наборы. Файл при загрузке не переписывается; редактор при сохранении пишет `breaks_with` явно (раздел 6). Если `breaks_with` в файле есть, `breaks_lie_on` движок не читает.
   - **Слом.** `_lie_breaks` проверяет `requires_broken_lies` (9.2, без изменений) и наборы. `requires_evidence` работает как раньше: ложь, сломанная набором без связанной улики, открывает `content_basic`; связанная улика, показанная потом, открывает `content_full`. Цепочка Аркадия (нож при несломанных «встрече» и «ноже») сохраняется: показ и пересказ запоминаются, и ложь ломается сама, когда откроется цепочка.
   - **Пересказ.**
     - Варианты `cite` в `TurnOptions.build` строятся не из `contradictions`, а из пунктов `testimony_retold` несломанных лжей текущего персонажа. Вариант появляется для каждой пары «показание + форма», которую игрок услышал и ещё не пересказывал этому лжецу в этой форме.
     - Выбор варианта пишет `"<лжец>|<fact_id>|<basic|full>"` (форма журнала `heard`) в новое `state.retold` (без повторов: второй такой же пересказ ничего не добавляет) и сам ложь не ломает. Пункт без `form` засчитывается пересказом в форме `basic` или `full`, пункт с `"form":"truth_full"` — только `full`. Пересказ полной формы после неполной — новый пересказ, не повтор.
     - `break_lies` и `admit` появляются, только если пересказ собрал набор (и выполнены `requires_broken_lies`); тогда признание идёт как сейчас (`restart`, `_admit_note`).
     - Охрана из 9.1/9.2 в `_present_grants` / `_cite_ok` переписывается под наборы. `contradictions` в слом больше не входят.
   - **Свидетель, который сам врёт.**
     - Пересказ не засчитывается, пока у владельца пересказанного показания есть несломанная ложь «на ту же тему» (кроме самого пересказанного показания). «Та же тема» = у этой лжи и у взламываемой есть общая улика в `related_evidence_ids`. Если у одной из них связанных улик нет, темы не пересекаются.
     - Проверка идёт в каждом `_resolve`: когда ложь свидетеля сломана, сохранённый пересказ засчитывается сам, повторять его не нужно.
     - Определение нарочно простое: смысловые пересечения без общей улики оно не ловит, и автор учитывает это в наборах. Пример из встроенного дела: Павел о кухне (`fact_pavel_arkady_kitchen`) против Аркадия засчитывается только после слома лжи Павла о Мире и ноже — у обеих лжей общая улика, нож.
   - **«Под сомнением».**
     - Ложь под сомнением, если она не сломана, но хотя бы один пункт какого-то набора выполнен или пересказ сохранён, но не засчитан. `RulesEngine.doubt(fact_id)` возвращает, что предъявлено: названия улик и пересказы (кто сказал, текст из блокнота, засчитан ли). Отдельно это не хранится, а вычисляется.
     - В пакете у строки лжи пометка: `k3 [ЛОЖЬ, ПОД СОМНЕНИЕМ]: <ложь>. Тебе уже предъявили: слова Павла «…»; улику «…». Защищайся в своей манере: если это сказал тот, к кому ты плохо относишься (см. отношения), — он наговаривает; если свидетель сам врёт — «а вы ему верите?». Правду не признавай.` У «Может соврать» строка остаётся `[ЛОЖЬ, МОЖНО ОГОВОРИТЬСЯ, ПОД СОМНЕНИЕМ]` с той же оговоркой; сомнение оговорку не убирает и новых текстов не добавляет.
     - Пометка идёт только этому персонажу. Тексты скрытой правды и чужих закрытых показаний в неё не попадают.
   - **Предъявить против показания.**
     - `RulesEngine.confront(agent_id, statement_id, evidence_id)`, где `statement_id = "<fact_id>|<form>"` — строка журнала (`heard`). Это тот же показ улики (`_present` → `_resolve`) плюс вердикт по выбранному показанию. Правило слома не меняется: выбор показания даёт точность и контекст, а не новое условие. Если эта улика ломает другую ложь этого персонажа, та ломается, а в журнале пишется «разоблачено также: …».
     - Вердикт считается по `fact_id` выбранной строки, независимо от формы. Если `fact_id` — правда, вердикт `not_refuted` (кроме `repeat`). `holds` и `doubt` возможны только для несломанной лжи. Для лжи, уже сломанной до этого показа, — только `completed` (эта улика при `requires_evidence` открыла `content_full`) или `already`.
     - Вердикты движка (проверяются по порядку; в скобках — что видит игрок):
       - `repeat` — у этого персонажа уже был `confront` с тем же `fact_id` (любая форма) и той же уликой, эффекта нет («Уже предъявляли»);
       - `refuted` — выбранная ложь сломана этим показом («Опровергнуто»);
       - `holds` — улика собирает набор, но не сломаны `requires_broken_lies` («Не опровергает»);
       - `doubt` — улика входит в набор, но набор не собран («Не опровергает»);
       - `completed` — ложь была сломана без связанной улики, это связанная улика при `requires_evidence` («Полное признание»);
       - `already` — ложь уже сломана полностью; бывает при предъявлении против строки признания (правда этой лжи) после полного признания («Уже признано»);
       - `not_refuted` — всё остальное, в том числе любое правдивое показание и промах («Не опровергает»).
     - Решение Тимура 2026-11-25: игрок не отличает `holds` и `doubt` от правды и промаха — для всех трёх он видит одно и то же «Не опровергает». Движок хранит настоящий вердикт (в `confrontations`), и в промпт персонажа идёт настоящий; разница видна игроку только по поведению персонажа. Штрафа за перебор улик нет.
   - **Состояние.** В `GameState` два новых необязательных поля: `retold: Array[String]` и `confrontations: Array[Dictionary]` (`{turn, agent_id, statement_id, evidence_id, verdict, also_broken: [fact_id]}`; `verdict` — настоящий вердикт движка, игроку он показывается по таблице выше). В старых сохранениях их нет, они читаются как `[]`. Снимок хода из 9.9 включает оба поля, так что откат посреди хода их тоже откатывает.
   - **Промпт.**
     - Ход-предъявление идёт так: `Game.confront(agent_id, statement_id, evidence_id, text)` → `_turn` со строкой события, которую видит только этот персонаж: «Следователь предъявляет улику «X» против твоих слов «<текст показания>». Итог проверки: …» — в промпт идёт настоящий вердикт движка. `RulesEngine.confront` вызывается внутри `_turn` после снимка хода 9.9, как `present_evidence`. Если улика этому персонажу уже показана, показ не повторяется (`shown` не меняется), но вердикт считается; `repeat` — только при той же паре. В `_last` хранятся `statement_id` и `evidence_id`, и «Повторить» (9.16, 9.28) повторяет тот же `confront` тому же персонажу.
     - При `not_refuted` / `holds` / `doubt` / `already` / `repeat` добавляется: «Это тебя не опровергает: держись своей версии, можешь оспорить, объяснить или уйти от ответа. Ничего сверх блока ЧТО ТЫ МОЖЕШЬ СКАЗАТЬ не признавай». При `refuted` / `completed` — нынешний пакет с [ПРАВДА] и записка «признай только это».
     - Сжатие блокнота 9.10 не выбрасывает записи, которые стоят в пунктах `testimony_retold` несломанных лжей этого персонажа. Это правило заменяет прежнее про записи противоречий.
   - **Голосом — как сейчас.** «Вот журнал охраны, а вы говорили…» идёт по нынешнему пути `present` / подсказки и ломает так же. Новых вариантов «улика × показание» в «ВЫБОРЕ» нет, промпт не растёт.
   - **Интерфейс** (`ui/screens/notebook.gd`, `interrogation.gd`).
     - Блокнот, «Записи»: у каждой строки показания, у правды тоже, кнопка «Предъявить улику» → доска открытых улик → переход в допрос этого персонажа и ход. Строку можно дополнить голосом или текстом, как в `_confirm_hint`.

## 10. Переразбивка «Дождя над Тенью» (данные, без новой механики)
**Решение.** Части правды не разносятся по отдельным показаниям, а складываются в двухступенчатое показание. Общий слой (что раньше открывало противоречие) идёт в `content_basic`, подробность (что раньше открывала улика) — в `content_full`. Улика стоит в `related_evidence_ids` и в `breaks_lie_on`, плюс `requires_evidence=true`. Тогда (в 1а-1) пересказ по противоречию ломает ложь и открывает общее, улика ломает её сразу и открывает всё; с PR 1в ломают только наборы `breaks_with`, см. «Наборы слома» ниже. Правило Тимура «разоблачена подробность — разоблачён и общий факт» выполняется само.

Все id сохраняются, включая `id` дела.   - «Чем можно сломать»: наборы строятся блоками «И»/«ИЛИ», пункты «Показана улика» и «Пересказаны слова» (с галочкой «только полная правда»); круговой тест сохраняет `breaks_with` встроенного дела; дело без `breaks_with` открывается с переведёнными наборами (9.35) и сохраняется с явным полем; каскад удаления убирает пункт из набора, опустевший набор удаляется, «Всегда врёт» без наборов — ошибка с «Перейти»; правила раздела 7 о наборах (включая «ни один набор не собрать») — по фикстуре;
  - новое дело только через поля проходит валидатор;
  - дело на 10 персонажей и 15 улик.
- Бокс: тесты и круговой тест на переразбитом деле.
- Устройство: выбор «персонаж → показание» с поиском, блоки условий и наборов «Чем можно сломать», длинные тексты.

**Часть 5. «Спросить персонажа»** (9.14, раздел 8)
- Тесты: регресс хода, песочница не меняет `Game.state` и файл слота, старт «как в начале дела», ход в песочнице не меняет `Game._turn_token` и `Game.is_busy`, в логах песочницы нет значений ключей (раздел 13).
- Бокс: живой ход в песочнице на тестовом ключе.
- Устройство: удобство, предупреждение о расходе.

- проверка проходимости симуляцией в редакторе (Тимур проверяет игрой сам).
- разбиение крупных файлов (`interrogation.gd`, `gemini_tts_backend.gd`) (перенос повтора сети 9.28 и merged-пути 9.32 в общий класс хода — не отложен, это часть 9.14);

- отдельная модель для STT (например `gemini-3.1-flash-lite`, чтобы не делить дневной лимит с диалогом) — только после теста качества; `gemini-3.6-flash` при MINIMAL распознал хуже;

- **мультиязычность** — отдельный план после итогового APK (решение Тимура 2026-11-22). Затронет: тексты дела и «живых персонажей», промпт персонажа (`PromptBuilder.RULES` и схема «по-русски»), `Summarizer`, промпт STT, интерфейс (`UiStrings`), голоса Chirp (`ru-RU`, `ru-RU-Chirp3-HD-*`), фильтр утечек (`ResponseValidator._tokens`: только `[A-Za-zА-Яа-яЁё]{7,}` и основа из 6 букв — под русский), `SpeechJunk._is_word` (только латиница, кириллица и цифры), междометия, подсказку STT 9.24. До этого плана новый код берёт язык из `GameLanguage` (раздел 0).

## 13. Безопасность ключей
- Ключи API (Gemini, в том числе тестовый, Chirp и любые другие) и иные секреты никогда не попадают в: файл дела (опубликованный и встроенный), черновик, резервную копию `.prev.json`, копию в `Documents/Detective/`, сохранение партии, логи песочницы и логи хода.
- Редактор не имеет полей для ключей; песочница берёт ключ только из настроек в памяти и никуда его не пишет; в логи идут только имя модели и коды ошибок.
- При записи сохранения уже действует `SaveState._without_secrets`; запись дела, черновика, резервной и внешней копии проходит такую же очистку (ключи вида `api_key`, `key`, `token`, `secret` не пишутся).
- Тест (часть 3, часть 5): в настройки подставляется фиктивный ключ-маркер, затем создаётся, публикуется дело, пишется копия в «Документы», делается ход в песочнице на мок-клиенте; все выходные файлы и захваченный лог сканируются — маркера нет.
- На боксе тестовый ключ проверяется только как `[ -n "$GEMINI_TEST_API_KEY" ]`, не печатается.

Открытых вопросов по плану нет.
