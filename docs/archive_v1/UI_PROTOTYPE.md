# Интерфейс текстового прототипа

Прототип текстовый, без голоса и 3D (диздок, раздел 10). Задача интерфейса — удобно допрашивать, предъявлять улики, ловить противоречия и обвинять. Красота вторична: простая тёмная «нуарная» тема, один шрифт с кириллицей, крупный текст.

Все экраны общаются только с автозагрузкой `Game` (`docs/ARCHITECTURE.md`, раздел 3.11). Примеры подписей ниже взяты из учебного дела и не относятся к настоящим делам.

## 1. Общая раскладка

Целевые устройства: **планшет на Android** (основное тестовое устройство, сенсор, альбомная и книжная ориентация) и **Windows** (мышь и клавиатура). Узкая телефонная раскладка отложена.

База проекта — 1280×800, `stretch mode = canvas_items`, `aspect = expand`. В альбоме этот масштаб не меняется. В портрете множитель `content_scale_factor` возвращает итоговый масштаб к 1, чтобы текст и кнопки были того же физического размера, что и лёжа (кнопка не ниже 48 px). Раскладка смотрит на размер окна: портрет (высота больше ширины) или ширина окна меньше 1000 px — портретная, иначе широкая.

**Широкая раскладка (≥ 1000 px): планшет в альбомной ориентации и окно Windows.** Три колонки.

```
┌──────────────┬─────────────────────────────┬──────────────────┐
│ Подозреваемые│        Допрос (чат)         │ Улики / Блокнот  │
│  (список)    │                             │  (вкладки)       │
└──────────────┴─────────────────────────────┴──────────────────┘
                          [Обвинить]  [Меню]
```

**Портрет (планшет стоя).** Чат на всю ширину, кнопка «Обвинить» сверху. Подозреваемые, улики и блокнот не делят экран с чатом: их открывают кнопки «←», «Улики» и «Блокнот», панель закрывается кнопкой «К допросу» или повторным нажатием.

**Узкая раскладка (< 700 px): телефон.** Один экран за раз и нижняя панель вкладок. По решению владельца в текстовом прототипе она не делается: ширина меньше 1000 px использует среднюю (планшетную) раскладку, в том числе уже 700 px.

**Сенсорное управление (планшет):**
- Всё делается касанием, ничего не зависит от наведения мыши: подсказки, которые на Windows показываются при наведении, на планшете открываются долгим нажатием.
- Прокрутка списков и чата — перетаскиванием пальцем (`ScrollContainer`), с инерцией.
- Экранная клавиатура в альбомной ориентации занимает до половины экрана: высота берётся из `DisplayServer.virtual_keyboard_get_height()`, чат и поле ввода поднимаются над клавиатурой, а боковые колонки на это время могут скрываться.
- Смена ориентации на лету перестраивает раскладку без потери состояния (текст в поле ввода, прокрутка чата).

**Мышь и клавиатура (Windows):**
- Enter — отправить вопрос, Shift+Enter — новая строка.
- Колесо мыши прокручивает, подсказки — при наведении.
- Минимальный размер окна 1024×640. Окно можно растягивать и разворачивать на весь экран (F11).

**Правила вёрстки:**
- Контейнеры Godot (`VBoxContainer`, `HBoxContainer`, `TabContainer`, `ScrollContainer`), без абсолютных координат.
- Раскладка переключается по ширине окна (см. выше) при каждом изменении размера окна или ориентации.
- Кнопки и пункты списков не меньше 48 px по высоте (палец).
- Учитывать безопасную область экрана (вырезы, жесты Android): `DisplayServer.get_display_safe_area()`.
- Базовый шрифт 18–20 px на планшете, 16–18 px на Windows. Масштаб текста — в настройках.
- Экранная клавиатура Android не должна закрывать поле ввода: при её появлении чат сдвигается вверх.
- Никаких чисел давления и полосок (диздок, раздел 10): состояние видно только по ремаркам.

## 2. Экраны

### 2.1 Главное меню и настройки

- Кнопки: «Новое дело», «Продолжить», «Начать заново», «Настройки». «Новое дело» открывает только встроенное дело, без выбора файла. «Продолжить» и «Начать заново» видны, когда для этого дела есть файл сохранения.
- **Настройки:**
  - поле «Ключ Gemini API» (скрыто точками, кнопка «показать»);
  - кнопка «Проверить связь» — короткий тестовый запрос;
  - выбор модели диалога (поле с подсказкой по умолчанию);
  - масштаб текста;
  - переключатель «Офлайн-отладка (без модели)» — `provider=mock`;
  - блок «Голос» (появляется на этапе «Голос», в текстовом прототипе скрыт):
    - «Озвучивать ответы» вкл/выкл;
    - «Источник голоса»: **Облачный** (по умолчанию) / **Встроенный в устройство**. Встроенный работает без сети и без расхода лимита, но звучит проще;
    - «Голосовой ввод»: Облачное распознавание / Через Gemini / Встроенное (если устройство поддерживает; иначе пункт неактивен и подписан «недоступно на этом устройстве»);
    - кнопка «Проверить голос» — произносит тестовую фразу;
    - громкость и скорость речи.
- **Ключа нет** — «Новое дело» открывает настройки с пояснением, где взять ключ (Google AI Studio → Get API key).

### 2.2 Брифинг дела

```
ПРОПАЖА В АРХИВЕ
──────────────────────────────
{briefing}

{intro_atmosphere — курсивом, мельче}

                 [Начать расследование]
```

- Если дело не прошло валидацию: экран «Дело повреждено» со списком ошибок (для автора).

### 2.3 Подозреваемые

Карточка на каждого агента:

```
┌────────────────────────────────┐
│ Орлов                           │
│ смотритель архива               │
│ «держится уверенно»             │  ← ремарка по полосе давления и эмоции
│ ● есть новое                    │  ← если открылась связанная с ним улика или противоречие
└────────────────────────────────┘
```

- Нажатие — открыть допрос этого агента.
- Если в деле задан `starting_agent_id`, этот агент стоит первым и подсвечен.

**Ремарки по полосе давления** (код, не модель):
- 0–24: «держится уверенно»;
- 25–49: «напряжён»;
- 50–74: «заметно нервничает»;
- 75–100: «на грани».

К полосе добавляется эмоция словом из раздела 13 диздока, например «злится».

### 2.4 Допрос

```
┌───────────────────────────────────────────┐
│ ← Орлов, смотритель архива   «напряжён»   │
├───────────────────────────────────────────┤
│ Вы: Во сколько вы ушли?                   │
│ Орлов: Как всегда, после семи.            │
│   (поправляет очки)                       │  ← remark из ответа модели, курсив
│ ── Открыта улика: Журнал посещений ──     │  ← системное событие
│ Вы: [предъявлена улика: Журнал посещений] │
│ Орлов: …                                  │
├───────────────────────────────────────────┤
│ Предъявить: «Журнал посещений»?   [Да] [×]│  ← подсказка EvidenceMatcher
│ [ Ваш вопрос…                     ] [ ➤ ] │
│ [Улики] [Блокнот]                   [🎤]  │  ← микрофон только на этапе «Голос»
└───────────────────────────────────────────┘
```

- **Голосовой ввод (этап «Голос»):** на планшете — кнопка 🎤: удерживать и говорить. На Windows — та же кнопка или горячая клавиша (удерживать пробел, когда поле ввода не в фокусе). Распознанный текст появляется в поле ввода, игрок может поправить его и отправить. Ответ агента озвучивается, а повторное нажатие на реплику повторяет озвучку.
- **Отправка:** Enter или кнопка ➤. Пока ждём модель, ввод заблокирован и видна строка «Орлов думает…».
- **Предъявить улику:** кнопка «Улики» → список открытых улик → «Предъявить». Каждой улике рядом виден значок, если её уже показывали этому агенту.
- **Подсказка «Предъявить …?»** появляется, когда `EvidenceMatcher` нашёл название улики в набранном тексте или модель вернула `mentioned_evidence`. Без подтверждения улика не предъявляется.
- **Агент требует улику** (`requested_evidence`) — системная строка «Орлов требует доказательств» и кнопка «Предъявить: …».
- **Системные события в ленте:** «Открыта улика: …», «Найдено противоречие: {description}», «Орлов больше не может это отрицать» (ложь сломана). Строка не блокирует ввод.
- **Ошибка сети или лимита:** строка с понятным текстом и кнопкой «Повторить»:
  - `offline` — «Нет связи с сервером»;
  - `rate_limited` — «Модель перегружена, подождите немного»;
  - `auth` — «Проверьте ключ в настройках».

### 2.5 Блокнот (услышанные утверждения)

```
[Записи] [Противоречия]         [фильтр: все ▾]
────────────────────────────────────────────
Орлов, ход 3:   «Ключ весь вечер был при мне.»
Лисина, ход 5:  «Видела у Орлова в руках связку ключей в 19:30.»
```

Вкладка «Противоречия»:

```
✓ Орлов говорит, что ключ был при нём, но …, ход 6
```

- Записи — обычный текст, без выбора. Агент, ход и формулировка. Текст берётся по форме: `content_basic`, `content_full` или `lie_text`.
- Фильтр подозреваемого действует на обе вкладки. На «Противоречиях» остаются пары, где выбранный подозреваемый владеет хотя бы одной стороной. «все» показывает всё.
- Противоречие появляется само, когда обе стороны уже в журнале. Строка: галочка, `description` и ход, если он записан. Пустой список — «—». Пустые записи — «Пока ничего не услышано.»

### 2.6 Доска улик

- Сетка карточек открытых улик: название, `short_description`, значок типа (документ, предмет, место).
- Нажатие — полный текст (`full_text`), рядом «Кому показана: …».
- Во время допроса на карточке есть кнопка «Предъявить {агенту}».
- Закрытые улики не показываются вовсе: игрок не должен знать, сколько их.

### 2.7 Обвинение

```
Обвинение
────────────────────────────
Кто:     [ Орлов        ▾ ]  ✓
Мотив:   [ выбрать…     ▾ ]
Способ:  [ выбрать…     ▾ ]
                 [Обвинить]
```

- Списки: агенты, `motive_options`, `method_options`.
- Проверка по разделу 4 диздока:
  1. Сначала проверяется убийца. Если он неверный — «Неверный подозреваемый», мотив и способ не оцениваются.
  2. Если убийца верный, проверяются мотив и способ, и игра пишет, что именно неверно.
- Угаданный элемент получает галочку ✓ и фиксируется: список блокируется, галочки сохраняются между попытками и в сохранении.
- Все три верны — экран победы: короткий итог и `truth_timeline` (теперь его можно показать) и кнопка «В меню».
- Число попыток не ограничено.

## 3. Тексты и язык

- Весь интерфейс на русском. Строки лежат в одном файле (`ui/strings.gd` или CSV для `TranslationServer`), чтобы потом добавить другие языки.
- Имена агентов, названия улик и тексты берутся только из файла дела.
