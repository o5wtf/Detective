# Протокол работы с языковой моделью

Точные шаблоны промптов, схема ответа и правила проверки. Реализуют: `PromptBuilder`, `GeminiClient`, `ResponseValidator`, `Summarizer` (см. `docs/ARCHITECTURE.md`). Основа — разделы 8, 9 и 11 диздока.

Примеры в документе взяты из выдуманного учебного дела «Пропажа в архиве» и не связаны с настоящими делами игры.

## 1. Главный принцип

Модель **не решает**, что ей можно говорить. Код собирает «пакет» — то, что агенту сейчас разрешено (диздок, раздел 8). Модель только формулирует ответ и сообщает, какие записи пакета она озвучила. Всё, чего нет в пакете, модель просто не знает:
- закрытые факты;
- правда по несломанной лжи;
- поле `background`;
- `truth_timeline`;
- `killer_id`.

## 2. Запросы

На один ход игрока — **один** запрос к модели (диалог). Изредка добавляется второй — резюме истории (раздел 7). Тон вопроса и упомянутые улики модель возвращает в том же ответе, отдельного запроса на классификацию нет: так экономится бесплатный лимит. Следствие: тон меняет давление после ответа, то есть со следующего хода (диздок, раздел 11).

### 2.1 Вызов

```
POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent
x-goog-api-key: {ключ}
Content-Type: application/json
```

Используется `generateContent`: это запрос без хранения состояния на сервере, историю передаём сами. Google сейчас рекомендует для новых проектов Interactions API, но `generateContent` полностью поддерживается. Переход возможен позже внутри `GeminiClient`, остальная игра этого не заметит.

### 2.2 Тело запроса

```json
{
  "systemInstruction": { "parts": [ { "text": "<СИСТЕМНЫЙ ПРОМПТ, раздел 3>" } ] },
  "contents": [ { "role": "user", "parts": [ { "text": "<ПРОМПТ ХОДА, раздел 4>" } ] } ],
  "generationConfig": {
    "responseMimeType": "application/json",
    "responseJsonSchema": { "<СХЕМА, раздел 5>": "" },
    "temperature": 0.9,
    "maxOutputTokens": 16384,
    "thinkingConfig": { "thinkingLevel": "MINIMAL" }
  },
  "safetySettings": [
    { "category": "HARM_CATEGORY_HARASSMENT",        "threshold": "BLOCK_ONLY_HIGH" },
    { "category": "HARM_CATEGORY_HATE_SPEECH",       "threshold": "BLOCK_ONLY_HIGH" },
    { "category": "HARM_CATEGORY_SEXUALLY_EXPLICIT", "threshold": "BLOCK_ONLY_HIGH" },
    { "category": "HARM_CATEGORY_DANGEROUS_CONTENT", "threshold": "BLOCK_ONLY_HIGH" }
  ]
}
```

- **Схема ответа.** `responseJsonSchema` — обычный JSON Schema, его сейчас рекомендует документация Gemini. Старое поле `responseSchema` (подмножество OpenAPI, типы `OBJECT`, `STRING`…) тоже работает. Если выбранная модель не примет `responseJsonSchema`, `GeminiClient` переключается на `responseSchema` с той же схемой, переведённой в этот формат.
- **Модель** одна и для реплики, и для резюме. В настройках ровно три, список выбран по замеру на платном ключе:
  - `gemini-3.5-flash-lite` — по умолчанию;
  - `gemini-3.1-flash-lite`;
  - `gemini-3.6-flash`.

  Смена в выпадающем списке сразу перечитывает клиент. Автоматической смены модели нет. Сохранённая модель не из списка (например `gemini-3.5-flash`) заменяется на `gemini-3.5-flash-lite`, затем пишется `settings_version=4`. Флаг «Озвучка» при этой миграции, если его ещё не было, записывается выключенным, а движок — `system`.
- **Бесплатный уровень:** Google может использовать запросы для улучшения своих продуктов. Для прототипа это приемлемо. Расход в настройках считается по платному прайсу: входные токены и выходные вместе с рассуждениями.
- **Рассуждения.** В запрос явно уходит `thinkingLevel` = `MINIMAL`. Если модель отвечает 400, тот же запрос повторяется с `LOW`, и принятый уровень запоминается для этой модели. В конфиге можно задать `LOW` сразу. Проверка связи thinking не шлёт.
- **Фильтры** `BLOCK_ONLY_HIGH`: в детективе есть насилие и взрослые темы, слишком строгие фильтры будут рвать допрос.

### 2.3 Разбор ответа

- **Текст:** `candidates[0].content.parts[*].text`. Части с `"thought": true` пропускаем, остальные склеиваем и разбираем как JSON.
- **`finishReason`:**
  - `STOP` — ответ нормальный;
  - `MAX_TOKENS` или оборванный JSON — одна повторная попытка той же модели с лимитом не ниже 16384. Второй такой ответ принимается, если JSON уже собран;
  - `SAFETY`, `PROHIBITED_CONTENT`, `BLOCKLIST` — `blocked`;
  - любое другое значение — `bad_response`.
- **`promptFeedback.blockReason`** задан — тоже `blocked`.
- **HTTP-ошибки** — по `docs/ARCHITECTURE.md`, раздел 3.6. Коротко: таймаут, 429, 502, 503 и 504 повторяют ту же модель, пауза берётся из `RetryInfo.retryDelay` (иначе заголовок `Retry-After`, иначе 1 с), не больше двух повторов. Ход целиком не длиннее 25 с. 401/403 и 400 с `API_KEY_INVALID` → `auth`; прочий 400 не считается ошибкой ключа; 404 → модель недоступна, другой модели нет; прочий 5xx → один повтор той же модели; нет сети → `offline`. В тексте ошибки есть имя модели, ключ вырезан. После исчерпания повторов игрок видит кнопку «Повторить».

## 3. Системный промпт (шаблон)

`{...}` — подстановки. Строки в `[...]` добавляются по условию.

```
Ты играешь персонажа в детективной игре-допросе. Игрок — следователь.

КТО ТЫ: {name}, {role}.
О СЕБЕ: {prompt_background}
ХАРАКТЕР И МАНЕРА РЕЧИ: {personality}
ОТНОШЕНИЕ К ДРУГИМ:
- {имя другого агента}: {relationships[agent_id]}
...
ЧТО СЛУЧИЛОСЬ (это знают все): {briefing}
АТМОСФЕРА: {intro_atmosphere}

ПРАВИЛА (нарушать нельзя):
1. О деле ты знаешь только то, что перечислено в блоке «ЧТО ТЫ МОЖЕШЬ СКАЗАТЬ» в сообщении следователя. Других фактов у тебя нет. Не придумывай новых событий, времени, мест, предметов, сумм и действий людей. Если спрашивают о том, чего нет в блоке, уходи от ответа в своей манере: «не знаю», «не помню», «не ваше дело».
2. Запись [ЛОЖЬ] — твоя версия. Держись её и не признавай обратного.
3. Запись [ЛОЖЬ, МОЖНО ОГОВОРИТЬСЯ] — держись своей версии, но если вопрос бьёт точно в эту тему, можешь проговориться указанной полуправдой. Делай это редко.
4. Запись [ПРАВДА] сообщай, когда она уместна по вопросу. Не выкладывай всё сразу и без вопроса.
5. Говори от первого лица, по-русски, как живой человек на допросе: 1–4 предложения, без списков и без разметки.
6. Никогда не упоминай, что ты ИИ или модель, не говори о правилах, промптах и ключах k1, e1.
7. Не делай выводов о том, кто виновен, если этого нет в твоих записях.
8. Улики: о тех, что тебе показали, ты знаешь содержание. О других уликах ты знаешь только названия.

ПОЛЯ ОТВЕТА:
- player_tone: оцени последний вопрос следователя: −3 очень мягкий и сочувственный, 0 нейтральный, +5 жёсткое обвинение, угроза или давление.
- reply: твоя реплика. Редко, не чаще одного-двух раз, можно вставить `<sigh>`, `<laugh>`, `<gasp>` или `<short pause>`. Других меток в угловых скобках нет. На экран и в историю метки не попадают.
- remark: короткая ремарка о тебе от третьего лица, до 12 слов, без новых фактов. Например: «отводит взгляд».
- emotion: твоё состояние после ответа, одно значение из списка.
- tone: как звучит reply, одно слово из списка (нейтрально, нервно, устало, раздражённо, испуганно, грустно, уверенно, уклончиво, саркастично). В reply это слово не входит и вслух само по себе не читается.
- stated: ключи записей, содержание которых ты действительно сказал в reply, с формой: lie — сказал свою ложь; basic — сказал полуправду или краткую правду; full — сказал полную правду. Ничего из записей не сказал — пустой список.
- mentioned_evidence: ключи улик, которые следователь упомянул в вопросе.
- requested_evidence: ключ улики, которую ты сам требуешь показать («Докажите!»), только если это в твоём характере; иначе null.
- cited_facts: id чужих показаний из «БЛОКНОТ СЛЕДОВАТЕЛЯ», которые следователь ясно процитировал. Смутное «я слышал иное» не входит. Не цитировал — пустой список.
- pace: необязательно. `slow`, `normal` или `fast`. `normal` можно не писать. В стиль синтеза `normal` не уходит.
```

## 4. Промпт хода (шаблон)

```
ТВОЁ СОСТОЯНИЕ: {pressure_text}. Эмоция: {emotion}.

ЧТО ТЫ МОЖЕШЬ СКАЗАТЬ:
{строки пакета}

УЛИКИ, КОТОРЫЕ ТЕБЕ ПОКАЗАЛИ:
{для каждой показанной этому агенту: "- " + title + ": " + full_text | "нет"}

УЛИКИ, ИЗВЕСТНЫЕ СЛЕДОВАТЕЛЮ (только названия):
{для каждой открытой: ключ e1… + " — " + title | "нет"}

БЛОКНОТ СЛЕДОВАТЕЛЯ:
{чужие показания: id | кто сказал | короткий текст | "пусто"}

ВЫБОР:
Если есть что выбирать, первый ключ ответа — `chosen`, массив номеров. Бери только то, что последняя реплика следователя говорит прямо и по смыслу. Сомневаешься — номер «ничего». Если выбора нет, поля `chosen` нет.
`mentioned_evidence` и `requested_evidence` на открытие улик не влияют.

РАНЕЕ В РАЗГОВОРЕ: {summary | "—"}

ПОСЛЕДНИЕ РЕПЛИКИ:
{до 6 последних сообщений: "Следователь: …" / "{name}: …"}

[СОБЫТИЕ: {event_note}]
ВОПРОС СЛЕДОВАТЕЛЯ: {player_text}
```

**Строки пакета** — по `PacketEntry.mode`:

| mode | Строка |
|---|---|
| `full` | `{key} [ПРАВДА]: {content_full}` |
| `basic` | `{key} [ПРАВДА]: {content_basic}` |
| `lie` | `{key} [ЛОЖЬ]: {lie_text}` |
| `lie_or_basic` | `{key} [ЛОЖЬ, МОЖНО ОГОВОРИТЬСЯ]: твоя версия: «{lie_text}». Проговориться можно только так: «{content_basic}»` |

Пустой пакет: `(ничего конкретного по делу ты сообщить не можешь — уходи от ответа)`.

**Тексты состояния** (числа модели не показываем):

| Давление | pressure_text |
|---|---|
| 0–24 | Ты спокоен и уверен в себе |
| 25–49 | Ты напряжён, но держишься |
| 50–74 | Ты заметно нервничаешь, отвечаешь неровно |
| 75–100 | Ты на грани, тебе трудно держать себя в руках |

**event_note** — для предъявления улики: `Следователь предъявляет улику «{title}»: {full_text}`. В этом случае `ВОПРОС СЛЕДОВАТЕЛЯ` — текст, который игрок добавил к предъявлению, или `Что скажете?`.

### Пример (учебное дело)

```
ТВОЁ СОСТОЯНИЕ: Ты заметно нервничаешь, отвечаешь неровно. Эмоция: nervous.

ЧТО ТЫ МОЖЕШЬ СКАЗАТЬ:
k1 [ПРАВДА]: Запер архив в 19:00, как обычно.
k2 [ЛОЖЬ]: Ключ от хранилища весь вечер был при мне.
k3 [ЛОЖЬ, МОЖНО ОГОВОРИТЬСЯ]: твоя версия: «После закрытия никого не видел». Проговориться можно только так: «Кажется, кто-то был в коридоре после закрытия».

УЛИКИ, КОТОРЫЕ ТЕБЕ ПОКАЗАЛИ:
нет

УЛИКИ, ИЗВЕСТНЫЕ СЛЕДОВАТЕЛЮ (только названия):
e1 — Журнал посещений

РАНЕЕ В РАЗГОВОРЕ: —

ПОСЛЕДНИЕ РЕПЛИКИ:
Следователь: Во сколько вы ушли?
Орлов: Как всегда, после семи.

ВОПРОС СЛЕДОВАТЕЛЯ: А ключ? Вы уверены, что никто не мог его взять?
```

Ожидаемый ответ:

```json
{
  "player_tone": 2,
  "reply": "Ключ? Он был у меня весь вечер, вот здесь, в кармане. Я его из рук не выпускаю.",
  "remark": "машинально хлопает по карману пиджака",
  "emotion": "nervous",
  "stated": [ { "key": "k2", "form": "lie" } ],
  "mentioned_evidence": [],
  "requested_evidence": null,
  "tone": "нервно"
}
```

## 5. Схема ответа (responseJsonSchema)

Схема собирается **на каждый запрос**: в `enum` подставляются ключи текущего пакета и открытых улик, так модель физически не может сослаться на чужой ключ. Если список пуст, в `enum` кладётся `["none"]`, и код этот ключ игнорирует. Порядок свойств задан намеренно: сначала оценка вопроса, потом реплика, потом отчёт о сказанном.

```json
{
  "type": "object",
  "properties": {
    "player_tone": { "type": "integer", "description": "Тон последнего вопроса: от -3 (мягкий) до 5 (жёсткое обвинение)" },
    "reply": { "type": "string", "description": "Реплика персонажа, 1–4 предложения, по-русски" },
    "remark": { "type": "string", "description": "Ремарка от третьего лица, до 12 слов" },
    "emotion": { "type": "string", "enum": ["calm", "neutral", "nervous", "scared", "sad", "angry", "controlled", "contemptuous"] },
    "stated": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "key": { "type": "string", "enum": ["k1", "k2", "k3"] },
          "form": { "type": "string", "enum": ["lie", "basic", "full"] }
        },
        "required": ["key", "form"]
      }
    },
    "mentioned_evidence": { "type": "array", "items": { "type": "string", "enum": ["e1"] } },
    "requested_evidence": { "type": ["string", "null"], "description": "Ключ улики e1… или null" },
    "tone": { "type": "string", "enum": ["нейтрально", "нервно", "устало", "раздражённо", "испуганно", "грустно", "уверенно", "уклончиво", "саркастично"] }
  },
  "required": ["player_tone", "reply", "remark", "emotion", "stated", "mentioned_evidence", "requested_evidence", "cited_facts", "tone"],
  "propertyOrdering": ["player_tone", "reply", "remark", "emotion", "stated", "mentioned_evidence", "requested_evidence", "cited_facts", "tone"]
}
```

Границы чисел (`minimum`/`maximum`) в схему не кладём, их проверяет код (раздел 6). Документация Gemini советует так делать, чтобы схема оставалась простой.

**Формы и диздок.** В журнал услышанного попадают формы `lie`, `basic`, `full` (диздок, раздел 9). Противоречия (диздок, раздел 14) читают их так: `truth` — услышано `basic` или `full`, `truth_full` — услышано `full`, `lie` — услышано `lie`.

## 6. Проверка ответа (ResponseValidator)

Проверки по порядку. «Нарушение» запускает перегенерацию (раздел 6.1). «Исправление» молча правится кодом.

1. **Формат.** JSON разобрался. Если реплика есть, недостающие поля заполняются значениями по умолчанию и это пишется в журнал как местное исправление. Пустая реплика — нарушение.
2. **stated.** Ключ есть в пакете, форма допустима для `mode`:
   - `lie` → `lie`;
   - `lie_or_basic` → `lie` или `basic`;
   - `basic` → `basic`;
   - `full` → `basic` или `full`.

   Недопустимая форма понижается до разрешённой (`full` → `basic` → `lie`), чтобы `register_statements` получил законную форму. Каждое такое исправление пишется в журнал (`validator fix …`) без текста факта. Чужой ключ отбрасывается. Повторы убираются, ключ `none` игнорируется. При `local_fixes=false` старое поведение: это нарушение.
3. **reply.** 1–4 предложения. Лишние предложения и хвост длиннее 700 символов обрезаются на месте. Разметка (`*`, `#`, маркеры списков) вычищается. Служебные слова («ИИ», «нейросеть», «языковая модель», «промпт», «k1», «e1» и т. п.) — нарушение.
4. **Утечка.** Код собирает «закрытый словарь» агента:
   - числа и время (например `19:00`, `2,5`) и редкие основы слов (слова от 7 букв, первые 6 букв);
   - источники: тексты его закрытых фактов, `content_full` фактов, открытых только на Basic, и правда несломанной лжи (кроме разрешённой оговорки);
   - из словаря вычитается всё, что встречается в разрешённых текстах: пакет, `prompt_background`, `personality`, `relationships`, показанные улики, `briefing`, история диалога, вопрос игрока, а также список частых слов.

   Если в `reply` есть число или время из закрытого словаря или хотя бы 2 разные закрытые основы — нарушение «возможная утечка». Пороги задаются в настройках. Все срабатывания пишутся в `user://logs/leaks.log` для настройки.
5. **Недосказанный отчёт.** Если в `reply` есть число или время, которое встречается ровно в одной записи пакета, а эта запись не указана в `stated`, код сам добавляет её с допустимой формой (для `lie` / `lie_or_basic` — `lie`). Так противоречия не теряются, когда модель забыла отчитаться.
6. **player_tone** вне −3…5 — исправление: обрезать до границы.
7. **emotion** вне списка — исправление: оставить прежнюю эмоцию.
8. **Ключи улик.** Ключ в `mentioned_evidence` или `requested_evidence` не из списка открытых улик — исправление: убрать.

### 6.1 Перегенерация и запасной ответ

- Повторная генерация — **только** при пустой реплике, служебном слове или утечке, и только одна. К промпту хода добавляется:
  `ИСПРАВЬ ОТВЕТ: {список нарушений человеческим языком}. Говори только то, что есть в блоке «ЧТО ТЫ МОЖЕШЬ СКАЗАТЬ».`
  При утечке закрытые сведения в тексте исправления **не называются**: пишется только «ты назвал сведения, которых нет в твоём списке, — не называй точного времени, чисел и подробностей, которых там нет».
- Ответ заблокирован фильтром (`blocked`) — одна повторная генерация с добавкой `Отвечай сдержаннее, без откровенных подробностей.`
- Снова не вышло — **запасной ответ** без запроса к модели:
  - реплика: «…Мне нечего добавить.» / «Я не буду об этом говорить.» / «Спросите что-нибудь другое.» (выбор по полосе давления);
  - ремарка: «молчит»;
  - `stated = []`, тон 0, эмоция прежняя.

  Состояние игры меняется только отметкой «был вопрос».
- Ошибки сети и лимита (`offline`, `timeout`, `rate_limited`, `auth`, `server`) — не перегенерация. Ход не состоялся, игрок видит понятное сообщение и кнопку «Повторить».

## 7. Резюме истории

Диздок, раздел 9: в промпт идут последние 6 реплик и краткое резюме более раннего. Реплика — одно сообщение (игрока или агента).

- **Когда.** После того как реплика уже показана: если за окном из 6 последних реплик лежит 6 или больше ещё не свёрнутых сообщений, они сворачиваются вместе со старым резюме. Получается примерно один запрос резюме на 3 хода после первых 6 реплик. Флаг `summary_after_reply=false` возвращает свёртку перед ответом.
- **Модель:** та же, что выбрана для диалога, `temperature` 0.2, thinking как у диалога.
- **Системный промпт:**
  ```
  Ты ведёшь протокол допроса. Сожми разговор в краткое резюме от третьего лица, по-русски, до 600 символов.
  Пиши только то, что было сказано: кто что утверждал, на чём настаивал, что признал, какие улики показали.
  Не добавляй выводов, догадок и сведений, которых не было в разговоре.
  ```
- **Сообщение:**
  ```
  ПРЕДЫДУЩЕЕ РЕЗЮМЕ: {summary | "—"}
  НОВЫЕ РЕПЛИКИ:
  {Следователь: … / {name}: …}
  ```
- **Схема:** `{"type": "object", "properties": {"summary": {"type": "string"}}, "required": ["summary"]}`.
- **Проверка:** длина до 900 символов (лишнее обрезается по предложению) и та же проверка утечек, что в разделе 6, пункт 4.
- **При ошибке или нарушении** — запасное резюме без модели: старое резюме плюс «{name} сказал(а): …» по записям журнала услышанного за эти ходы.

## 8. Настройки (`user://config.cfg`)

```ini
[llm]
provider="gemini"                    ; gemini | mock
api_key=""                           ; вставляется на экране настроек; в git и сборку не попадает
dialogue_model="gemini-3.5-flash-lite"   ; ещё gemini-3.1-flash-lite | gemini-3.6-flash
settings_version=4
thinking_level="MINIMAL"            ; MINIMAL | LOW
summary_after_reply=true
local_fixes=true
timeout_s=45
ping_timeout_s=32

[voice]
enabled=false                        ; «Озвучка», по умолчанию выключена
engine="system"                      ; system | gemini

[validator]
leak_max_stems=1                     ; 2 и больше закрытых основ — нарушение
log_leaks=true

[debug]
log_prompts=false                    ; писать промпты и ответы в user://logs/llm.log
```

Пример без ключа лежит в репозитории: `config/config.example.cfg`.
